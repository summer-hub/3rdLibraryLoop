# R-04 异步回调注册时序类

- **状态**: active
- **严重级别**: high（偶发/必现的主流程结果丢失，难排查）
- **适用范围**: JS 层通过事件回调接收原生结果的库（Promise 封装 native 调用 + 事件监听模式）
  - 预筛特征: JS 层存在 `new Promise` 内先调 native 方法再用 emitter.once/registerCallback 监听响应的代码；或固定字符串 transaction 标识
- **问题本质**: JS 层调用原生方法与注册结果监听的时序颠倒（先调用后注册），原生响应先于监听注册到达时结果丢失；或使用固定 transaction 字符串标识请求，并发/重入场景下响应混淆
- **检查点**:
  1. 定位 JS 层所有"Promise 封装 native 调用"的位置，检查是否先注册回调再调用 native
  2. 检查注册前是否清理旧监听（unregisterCallback），防止重复注册导致多次响应
  3. 检查请求标识（transaction）是否唯一（随机 UUID vs 固定字符串），并发调用是否会混淆响应
  4. 检查回调中对无效响应（空结果/错误码字段）是否过滤
- **错误特征**: `nativeXxx?.(data)` 在 `emitter.once(...)` 之前执行；transaction = 固定字符串（如 "webpage"）
- **正确特征**: 先 unregister 旧回调 → registerCallback 新回调 → 再调 native；transaction 用唯一标识（UUID）；回调内过滤无效响应后 resolve/reject
