# R-12 原生运行时资源析构时序类

- **状态**: active
- **严重级别**: high（偶发崩溃，crash rate 0.01% 级别，难复现）
- **适用范围**: C++ 层持有 JSI/Hermes 运行时引用（Runtime/WorkletRuntime）的库
  - 预筛特征: C++ 代码中含 jsi::Runtime / WorkletRuntime / Hermes GC 相关调用；析构函数中 reset workletRuntime
- **问题本质**: 原生运行时（如 Hermes）持有的 JSI 对象引用了已析构的原生对象（ShadowNode），析构顺序不当导致 GC 回收时访问野指针崩溃——uiWorkletRuntime 先于 UIManager 析构，GC 回收 ShadowNodeWrapper 时 ComponentDescriptorRegistry 已失效
- **检查点**:
  1. 检查析构函数中 uiWorkletRuntime_/workletRuntime_ 的 reset 顺序是否在 UIManager/hooks 之前
  2. 检查是否在 workletRuntime 析构前主动触发 GC（gc()）回收 JSI 对象
  3. 检查 GC 调用是否有异常保护（try-catch，失败不阻止析构）
  4. 检查 commitHook_/mountHook_ 的 reset 是否在 GC 之后、UIManager reset 之前
- **错误特征**: uiWorkletRuntime_.reset() 在 commitHook_.reset() 之前；无主动 GC 调用；析构顺序：先 reset hooks → 再 reset runtime
- **正确特征**: 先主动 GC → 再 reset hooks → 再 reset UIManager → 最后 reset runtime；GC 调用有 try-catch 保护
