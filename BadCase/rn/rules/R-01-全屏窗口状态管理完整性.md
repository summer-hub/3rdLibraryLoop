# R-01 全屏/窗口状态管理完整性类

- **状态**: active
- **严重级别**: high（核心功能不可用：全屏能力整体失效）
- **适用范围**: 对外声明媒体/窗口/系统能力（全屏、旋转、后台播放、画中画等）的库
  - 预筛特征: JS 层暴露 fullscreen/orientation/allowsFullscreenVideo 等接口；ArkTS 层使用 Web/Video/AVPlayer 等媒体组件；README 含"全屏""横屏"能力声明
- **问题本质**: 库声明了全屏/旋转类能力，但鸿蒙侧实现只覆盖"happy path"——缺少全屏事件监听、初始状态保存、多步操作失败回滚、组件销毁时窗口状态恢复中的任一环节，导致能力整体失效或状态残留
- **检查点**:
  1. 列出库对外声明的全屏/旋转/窗口类能力，逐项在鸿蒙侧实现中定位支撑代码（事件监听 + 窗口 API 调用）
  2. 检查进入全屏等多步窗口操作中，单步失败时是否有回滚逻辑（恢复方向/系统栏/布局）
  3. 检查组件销毁（aboutToDisappear）时是否恢复窗口初始状态（方向、沉浸式、系统栏），防止状态残留
  4. 检查异步窗口操作是否有状态标志防重入（如 isFullScreen 守卫）
- **错误特征**: 声明了全屏 prop 但 ArkTS 层无 onFullScreenEnter/onFullScreenExit 监听；或监听了事件但直接改布局，未调用 setPreferredOrientation/setWindowLayoutFullScreen；或全屏后组件销毁未恢复窗口状态
- **正确特征**: 完整链路 = 保存初始方向 → 监听全屏事件 → 串行执行方向+沉浸式设置（每步校验结果）→ 失败回滚 → 销毁时无条件恢复窗口状态
