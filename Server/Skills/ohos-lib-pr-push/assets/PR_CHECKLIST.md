# 三方库 PR 提交 Checklist（ohos-lib-pr-push 规范依据）

> 来源：[pr提交checklist.md](https://gitcode.com/gcw_N7oHqLFR/rn-libs-docs/blob/main/pr%E6%8F%90%E4%BA%A4checklist.md)（rn-libs-docs），本文件为执行时快照，供 SKILL 离线引用。适用于 cpf-rn / cpf-flutter / CPF-ApplicationTPC 三组织的源仓库 PR 提交。

## 一、前置条件：创建并关联 Issue

- PR **必须**关联一个已创建的 Issue
- 如无对应 Issue，需先新建，否则 PR 将不予评审

### Issue 必填内容

| 字段 | 说明 | 示例 |
|------|------|------|
| **问题标题** | 简明概括，带类型标签 | `[Bug] ScrollView 在 xxx 场景上滑动卡顿` |
| **问题描述** | 详细说明遇到的现象 | 在xxx场景，快速滑动时出现明显掉帧… |
| **复现步骤** | 逐步操作，确保可重现 | 1. 打开列表页 → 2. 快速下滑 → 3. 观察帧率下降 |
| **预期结果** | 期望的正确行为 | 滑动流畅，帧率稳定在 60fps |
| **实际结果** | 当前错误行为 | 滑动过程中帧率降至 20-30fps，界面卡顿 |
| **复现概率** | 必现 / 高频 / 偶发 | 必现（100%） |
| **环境信息** | 框架&库版本，系统版本，设备型号等 | RN0.72.101; react-native-webview@13.10.1; API22 |
| **DEMO(如有)** | 运行该DEMO可直接复现问题 | 最小代码段 |
| **日志/截图(如有)** | 报错日志、堆栈、截图、录屏 | 附带 systrace 截图及 logcat 输出 |
| **影响范围** | 受影响的功能模块 | 所有使用scrollview的场景 |

---

## 二、PR 提交要求

### 2.1 代码与测试用例同步提交

- **修复代码与对应测试用例必须同时提交**，不接受无测试的 PR
- 测试用例应覆盖：
  - 问题复现场景（验证 Bug 确实存在）
  - 修复后场景（验证修复有效）
  - 边界 / 异常情况（验证无副作用）

### 2.2 测试用例已存在的情况

若已有测试用例可覆盖本次修改，**必须在 PR 描述中说明**：

```
### 需触发的测试用例

- 本工程xxxx分支  `<path>/scroll-view.ts`
- RNT工程xxxx分支 `<path>/scroll-view.ts`
```

说明内容：
- 列出触发的测试文件及用例名称
- 确认运行结果（全部通过 / 部分通过需说明原因）

## 四、提交前检查（硬性要求）

| 检查项 | 要求 | 未通过处理 |
|--------|------|------------|
| **AI 代码扫描** | 提交前必须通过 AI 代码扫描（代码pr审查） | 不得提交，需修复后重新扫描 |
| **自测试通过** | 所有新增及已有测试用例通过 | 不得提交 |
