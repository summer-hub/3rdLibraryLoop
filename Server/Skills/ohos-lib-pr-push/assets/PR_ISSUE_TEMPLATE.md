# PR / Issue / 报告模板（ohos-lib-pr-push）

本文件包含三段模板：Issue body、PR body、最终报告。`{占位符}` 由执行时填充。

> 约定：Issue 标题格式为 `{分类}：{摘要}`，分类只能是 `Demo 需求` / `bug` / `咨询` 三选一，禁止 `[auto]` 等无意义前缀；PR 标题直接用 commitMessage 摘要（无前缀）；所有 body 临时文件写入 `/tmp`，流程结束后删除——工作目录只产出最终报告一个文档。

---

## 一、Issue Body 模板

```markdown
## {一句话说明本次提交的作用}

对 `{owner}/{repo}` 的自动修改提交。

### 提交作用

{2-5 句说明：为什么改、解决什么问题、达到什么效果}

### 修改点

| 序号 | 文件路径 | 修改类型 | 修改说明 |
|------|---------|---------|---------|
| 1 | {path} | 新增/修改/删除 | {具体修改说明} |

### 验证情况

{如有：测试用例执行结果、编译/覆盖率数据；如无写"见 PR CI"}

---
> 此 Issue 由 ohos-lib-pr-push 工作流自动创建
```

---

## 二、PR Body 模板

```markdown
## {一句话说明本次提交的作用}

### 修改内容

{2-5 句概述}

### 修改文件列表

| 序号 | 文件路径 | 修改类型 | 修改说明 |
|------|---------|---------|---------|
| 1 | {path} | 新增/修改/删除 | {具体修改说明} |

### 关联 Issue

Closes #{issue_number}

---
> 此 PR 由 ohos-lib-pr-push 工作流自动生成
```

> **必须**：`Closes #{issue_number}` 在创建 PR 时写入 body，不做事后 PATCH。

## 三、最终报告模板（ohos-lib-pr-push-report.md）

```markdown
# 三方库自动提 PR 报告

## 基本信息

| 项目 | 内容 |
|------|------|
| 源仓库（上游） | {upstreamUrl} |
| fork 仓库 | {forkRepoUrl} |
| 提交模式 | fork → 源仓库跨仓 PR |
| 工作分支（PR head） | {当前分支}（未切换分支） |
| PR 目标分支（base） | {上游同名分支 / default_branch（回退时标注）} |
| 执行时间 | {currentTime} |

## 执行结果

| 项目 | 内容 |
|------|------|
| 状态 | 成功 / 失败（{失败阶段}） |
| PR 地址 | {prUrl} |
| PR 编号 | !{prNumber} |
| Issue 地址 | {issueUrl} |
| Issue 编号 | #{issueNumber}（标题分类：{Demo 需求/bug/咨询}） |
| Issue 绑定 | 是 / 否（PR body 含 `Closes #{issueNumber}`） |
| CI 触发 | 是 / 否（评论 `Start build` 于原仓库 PR） |
| CHANGELOG | 已更新（英文条目含 Issue 链接）/ 跳过（未修改三方库内部源码） |

## 修改文件清单

| 序号 | 文件路径 | 修改类型 | 修改说明 |
|------|---------|---------|---------|
| 1 | {path} | 新增/修改/删除 | {具体修改说明} |

## CHANGELOG 更新

{判定为"需要"时：写入 CHANGELOG.md 的英文条目原文（含 Issue 链接）；判定为"不需要"时：跳过原因，如"本次仅涉及 demo 页面与测试用例，未修改三方库内部源码"}

## 错误信息

{如有失败步骤：失败阶段、原因、已完成的产物编号与链接}
```
