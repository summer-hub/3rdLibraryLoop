# 知识库查询指南

> 本文档说明如何查询鸿蒙知识库，补充大模型通用知识不够具体的场景。

---

## 1. 何时查询知识库

| 场景 | 是否查询 |
|------|----------|
| 通用编程任务（非鸿蒙） | ❌ 不需要 |
| 鸿蒙API使用，通用知识足够 | ❌ 不需要 |
| ArkTS特定约束，通用知识模糊 | ✅ 需要 |
| OpenHarmony特定最佳实践 | ✅ 需要 |
| 鸿蒙三方库检视的检查标准 | ✅ 需要 |
| ArkTS编译错误修复 | ✅ 需要 |
| ArkUI响应式/状态管理陷阱 | ✅ 需要 |

**判断原则**：当不确定通用知识是否准确覆盖鸿蒙特定行为时，查询知识库。

---

## 2. 查询流程

### 2.1 构建检索词

从SKILL需求中提取关键词，组合检索词：

**提取维度**：
- 技术栈：ArkTS、OpenHarmony、HarmonyOS、ArkUI
- 具体领域：内存泄漏、生命周期、状态管理、NAPI、权限
- 操作动作：检测、检视、修复、最佳实践

**组合示例**：
```
需求：检测ArkTS三方库内存泄漏
检索词：["ArkTS 内存泄漏", "OpenHarmony 生命周期泄漏", "ArkTS 事件监听清理"]
```

### 2.2 调用知识库工具

调用 `kb-server_` 前缀的知识检索工具（具体工具名通过 `gateway_list_tools` 获取）。

**调用策略**：
- 一次查询一个关键词
- 若返回不相关，调整关键词重试（最多3轮）
- 记录查询过的关键词，避免重复

### 2.3 结果处理

对知识库返回的内容分类处理：

| 内容类型 | 处理方式 | 放置位置 |
|----------|----------|----------|
| 检查清单 | 整合为检查项 | references/ 的检查文档 |
| 代码示例 | 提取关键模式 | assets/ 的模板中 |
| 最佳实践 | 精简引用 | SKILL.md body 对应Phase |
| 注意事项 | 精简引用 | SKILL.md body 或 references/ |
| 错误模式 | 记录为反模式 | references/ |

---

## 3. 知识融合原则

### 3.1 不照搬全文

知识库返回的内容可能很长，**不要**完整复制到SKILL中。应：
- 提取核心要点
- 精简为1-3句话引用
- 详细内容放入 references/，SKILL.md 中用链接引用

### 3.2 标注来源

在引用知识库内容时，标注来源：

```markdown
> 📖 来源：鸿蒙知识库，关键词"ArkTS 内存泄漏"
```

### 3.3 验证适用性

知识库返回的内容需验证是否适用于当前SKILL场景：
- API版本是否匹配（API 12+ vs 更低版本）
- 场景是否匹配（三方库 vs 系统应用）
- 约束是否仍然有效

## 4. 常见鸿蒙知识库查询场景

### 4.1 ArkTS 编译规范

检索词建议：
- `ArkTS 编译错误` — 常见编译约束
- `ArkTS 类型系统` — 类型限制
- `arkts-no-any` — 具体规则

### 4.2 ArkUI 响应式

检索词建议：
- `ArkUI 状态管理` — @State/@Prop/@Link
- `ArkTS @Builder 响应式` — @Builder 陷阱
- `ArkUI 组件生命周期` — 生命周期回调

### 4.3 鸿蒙性能与稳定性

检索词建议：
- `ArkTS 内存泄漏` — 泄漏检测
- `OpenHarmony 稳定性` — 崩溃分析
- `ArkTS 异步处理` — Promise/async
