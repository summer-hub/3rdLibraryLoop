# SKILL 定位指南

> 当经验条目没有关联的 skillDir 时，如何判断是否需要定位 SKILL 以及如何定位。

---

## 1. 定位流程

```
Step 1: 检查知识条目的 skillDir 字段
    ├── 非null → 直接使用该路径
    └── null → 进入 Step 2

Step 2: 检查经验内容是否显式提及SKILL
    ├── 经验中直接提到SKILL名称或步骤名 → 进入 Step 3
    └── 未显式提及 → 停止定位，所有内容归为知识类

Step 3: 精确定位（非语义推断）
    ├── 在经验内容中提取显式提及的SKILL名称 → 直接关联
    ├── 提取显式提及的步骤名/流程环节 → 搜索包含该步骤的SKILL
    └── 仍无法精确匹配 → 停止定位，内容归为知识类

Step 4: 确认关联
    ├── 精确匹配到 → 使用该SKILL目录
    └── 未精确匹配到 → 不进行SKILL修改，内容归为知识类
```

> ⚠️ **核心原则**：SKILL定位基于**显式证据**（经验中明确提到的SKILL名/步骤名），而非主题相关性或语义推断。主题相关不等于流程缺陷。

---

## 2. 显式提及的判断标准

经验内容满足以下任一条件才算"显式提及SKILL"：

| 判断条件 | 示例 | 说明 |
|----------|------|------|
| 直接提到SKILL的name | "TPCXTSCodeSkill应增加..." | 明确指向特定SKILL |
| 直接提到SKILL的具体步骤 | "阶段零的探查步骤遗漏了..." | 指向特定流程环节 |
| 直接提到SKILL的检查项 | "应增加对XX的检查" | 指向特定检查环节 |

**不算显式提及的情况**（以下不触发SKILL定位）：
- 经验提到某技术领域（如"测试""覆盖率"）但未指向具体SKILL
- 经验提到某工具行为（如"devecocli docs search不稳定"）但未指向SKILL流程
- 经验提到最佳实践（如"版本标注应同时..."）但未指向SKILL步骤缺陷

---

## 3. 关键词提取（仅用于已确认需要定位时）

当 Step 2 确认经验**显式提及了SKILL**后，提取关键词用于精确定位：

### 3.1 从经验内容提取

- 显式提到的SKILL名称（如 "TPCXTSCodeSkill"）
- 显式提到的步骤名（如 "阶段零""步骤1"）
- 显式提到的检查项或流程环节

### 3.2 从 taskDescription 提取（辅助）

- 原始任务描述中的操作动词和领域名词，用于辅助确认定位准确性

---

## 4. 匹配规则

### 4.1 精确名称匹配

经验内容直接提及某个SKILL的name → 直接关联。

### 4.2 步骤名匹配

经验内容提及某个步骤名/流程环节 → 在所有SKILL中搜索包含该步骤的SKILL。

> ⚠️ **禁止使用关键词重叠匹配**：即使经验关键词与某SKILL的description有大量重叠，只要经验未显式提及该SKILL的名称或步骤，就不进行关联。

---

## 5. 现有SKILL分类参考

| 分类 | SKILL | 典型关键词 |
|------|-------|-----------|
| task-planning | task-analysis, task-decomposition | 任务分析、拆解、验收标准 |
| meta-skill | skill-generator, knowledge-import | SKILL生成、知识导入、自我迭代 |
| 代码检视 | arkts-code-check, arkts-library-*-check | 代码质量、内存泄漏、稳定性、覆盖率 |
| 原生库 Demo | arkts-library-demo-* | Demo代码、覆盖率、场景 |
| 原生库 XTS | arkts-library-xts-* | XTS测试、用例、执行 |
| 接口规范 | arkts-library-interface-spec | 接口提取、规格 |
| 验收 | acceptance-check | 准出审核、验收测试 |

> 此表仅用于辅助理解SKILL分类，**不用于语义推断关联**。定位仍以显式提及为前提。
