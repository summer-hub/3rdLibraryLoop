# 严苛评分标准与计算规则

本文件定义 RN 鸿蒙化一致性检视的完整评分体系，包括扣分类型、豁免规则、归零规则、维度加权计算方法。

> 📖 **引用来源**：SKILL.md Phase 6 评分计算 + 严苛评分标准节的详细内容。

---

## 1. 严苛扣分制

采用**严苛扣分制**，从 100 分开始扣减，每个函数的对比结果**独立计算扣分**：

```
初始分数：100 分

扣分类型（函数级独立扣分）：
├── 致命问题：-15 分（最多扣 60 分）
│   ├── **原生注册缺失（JS/TS Spec注册的TM或Component在ArkTS Factory中未注册）** -15/实体名 ⛔跳过内部逐项检查
│   ├── 参数类型致命错误（如 boolean→string）............... -15/处
│   ├── OHOS 方法缺失（Android 有但 OHOS 无方法）.......... -15/方法（仅限已注册TM内部）
│   ├── OHOS 方法为 Stub（返回固定值无实际操作）........... -8/方法
│   ├── OHOS 方法返回错误而非实现.......................... -10/方法
│   ├── 返回值类型/语义完全错误........................... -10/处
│   ├── 函数行为致命不一致（核心逻辑完全不同）............. -15/方法
│   ├── 无文档说明的副作用（OHOS Prop影响额外功能点，Android/iOS无此影响且无文档解释）-15/处
│   └── 错误码硬编码固定值............................... -8/处
│
├── 严重问题：-12 分
│   ├── 函数行为严重不一致（核心逻辑部分不同）............. -12/方法
│   ├── 异常传播不完整................................... -6/方法
│   ├── 核心方法部分功能缺失............................. -12/方法
│   ├── 参数数量不匹配................................... -8/方法
│   ├── 有文档但不合理的副作用（文档标注了但理由不成立）.. -12/处
│   ├── 非rawProps核心属性默认值不一致且无文档（vs Android/iOS）-12/处
│   └── 返回值格式不标准................................. -6/方法
│
├── 中等问题：-8 分
│   ├── 边界处理不一致................................... -8/方法
│   ├── 错误消息缺少诊断信息............................. -4/处
│   ├── 类型精度丢失（int/double 精度问题）............... -5/处
│   ├── 空值处理不完整................................... -8/处
│   ├── 非rawProps次要属性默认值不一致且无文档（vs Android/iOS）-8/处
│   └── 事件数据格式不一致............................... -6/处
│
├── 轻微问题：-3 分
│   ├── 方法命名不一致（无合理理由）..................... -3/方法
│   ├── 术语/常量命名不一致............................. -2/处
│   ├── 默认值差异....................................... -4/处
│   ├── 有文档说明的合理副作用（归入平台适配合理性维度）.. -3/处
│   ├── 非rawProps属性默认值不一致但有文档合理差异........ -3/处
│   └── 平台差异未文档化................................. -3/处
```

## 2. 文档标注不支持豁免规则

🟢 **豁免规则**（文档标注不支持→不扣分）：

| 项目 | 说明 |
|------|------|
| 适用条件 | OHOS 仓库的 README、接口规格说明、或源码注释中明确标注该接口/属性/函数/组件不支持（如 "HarmonyOS Support: No"、"Android only"、"(不支持)" 等） |
| 豁免对象 | 属性、接口、函数、方法、Command、事件、组件等所有检视项 |
| 豁免效果 | 标记为"🟢 文档标注不支持，豁免不扣分"，0分，不计入致命/严重问题计数 |
| 文档来源优先级 | 接口规格说明 > OHOS README > 源码注释 > 上游文档 |
| 验证要求 | 必须在报告中引用文档标注的具体位置（文件:行号 + 标注原文） |

### 判定流程

1. **识别缺失项**：在逐项检视中发现 OHOS 未实现某项
2. **检查文档标注**：依次查找以下文档来源，判断是否标注为不支持：
   - **接口规格说明**（如 `接口规格说明.md`）：查找该接口行，检查是否有 `(Android only)`、`(iOS only)`、`(不支持)` 等标注
   - **OHOS README**（如 `harmony/README.md` 或仓库根目录 README）：查找 "HarmonyOS Support" 列，值为 "No" 或空；查找 "Platform" 列，值非 "All" 且非 "HarmonyOS"
   - **源码注释**（如 `.ets`/`.ts`/`.cpp` 文件中的注释）：查找 `// not supported`、`// Android only`、`// TODO: 鸿蒙不支持` 等
   - **上游文档**（如 RN 库的 `docs/Reference.md`）：查找平台限制标注
3. **判定规则**：
   - 🟢 **文档已标注不支持** → 豁免，0分，报告中标注"🟢 文档标注不支持，豁免不扣分（来源：文件:行号）"，**不计入致命/严重问题计数**
   - ❌ **文档未标注不支持** → 按原扣分规则扣分

> ⚠️ **重要**：此豁免规则适用于所有检视维度（方法缺失、Command缺失、Prop缺失、事件缺失等），不仅限于特定的检查点。

### 豁免项输出格式

```markdown
| # | 检视项 | 缺失描述 | 文档标注 | 文档来源 | 豁免判定 | 扣分 |
|---|--------|---------|---------|---------|---------|------|
| 1 | `clearFormData` Command | ArkTS未注册 | ✅ Android only, HarmonyOS Support: No | README.md:380 + 接口规格说明.md:46 | 🟢 豁免不扣分 | 0 |
| 2 | `allowFileAccess` Prop | ArkTS未实现 | ❌ 无标注 | — | ❌ 按规则扣分 | -15 |
```

## 3. 归零规则

| 条件 | 结果 |
|------|------|
| 不存在鸿蒙代码 | 0 分 |
| 鸿蒙代码无实际实现（全部 Stub） | 0 分 |
| 致命问题 ≥ 4 个 | 0 分 |
| 致命问题 ≥ 3 个 + 严重问题 ≥ 2 个 | 0 分 |
| 累计扣分超过 60 分 | 0 分 |

最低分数：0 分

---

## 4. 评分等级

| 分数区间 | 等级 | 含义 |
|----------|------|------|
| 90-100 | 优秀 | 鸿蒙化实现与原库高度一致，无致命/严重问题 |
| 80-89 | 良好 | 存在少量中等问题，核心功能完整 |
| 70-79 | 一般 | 存在严重问题，部分方法实现偏差 |
| 60-69 | 较差 | 多个严重问题，功能缺失明显 |
| 50-59 | 严重不足 | 致命问题存在，核心功能不可用 |
| <50 | 极差 | 实现一致性严重不足，需全面重新实现 |

## 5. 检视维度与权重

| 维度编号 | 维度 | 权重 | 满分 | 说明 |
|----------|------|------|------|------|
| 维度1 | API 契约一致性 | 35% | 35 | 方法签名、参数类型、返回值、事件/回调对比 |
| 维度2 | 平台实现一致性 | 30% | 30 | Android vs OHOS、iOS vs OHOS 函数级功能对比；副作用&关联影响（无文档/不合理部分）；非rawProps属性默认值（无文档/不合理部分） |
| 维度3 | RN 架构一致性 | 20% | 20 | TurboModule/NativeModule/NAPI 桥接一致性 |
| 维度4 | 平台适配合理性 | 15% | 15 | 合理差异判定、平台特有场景处理；副作用&关联影响（有文档且合理部分）；非rawProps属性默认值（有文档且合理部分） |

## 6. 维度加权扣分计算

```
基础分 = 100

维度编号与权重：
| 维度编号 | 维度名称 | 权重 | 扣分上限 |
|----------|---------|------|---------|
| 维度1 | API 契约一致性 | 35% | -35 |
| 维度2 | 平台实现一致性 | 30% | -30 |
| 维度3 | RN 架构一致性 | 20% | -20 |
| 维度4 | 平台适配合理性 | 15% | -15 |

维度扣分来源映射（按检查项维度标签 + 条件路由规则）：

维度1（API 契约一致性，35%）：
  → 四类型所有 ①契约一致性 检查项（无条件路由）

维度2（平台实现一致性，30%）：
  → 四类型所有 ②平台实现差异 检查项（主映射逻辑不一致、函数行为不一致等）
  → Props 副作用&关联影响：无文档说明的副作用（-15）、有文档但不合理的副作用（-12）
  → 非 rawProps 属性默认值：无文档说明的不一致（核心 -12、次要 -8）、有文档但不合理的差异
  → Phase 5.3 平台差异记录中不合理差异

维度4（平台适配合理性，15%）：
  → Props 副作用&关联影响：有文档说明且合理的副作用（-3，归入此维度）
  → 非 rawProps 属性默认值：有文档说明且合理的差异（-3，归入此维度）
  → Phase 5.3 平台差异记录中合理差异
  → 平台差异未文档化（-3）

维度3（RN 架构一致性，20%）：
  → 四类型所有 ③架构桥接一致性 检查项
  → Phase 5.1 NAPI/C++ 桥接 + Phase 5.2 NativeModule 架构
```

### 条件路由规则（核心）

副作用&关联影响、非rawProps属性默认值两个检查项的扣分，不按①②③标签硬绑定维度，而根据判定结果路由：

| 判定结果 | 归入维度 |
|----------|----------|
| 无文档说明 → | 维度2（平台实现一致性） |
| 有文档但不合理 → | 维度2（平台实现一致性） |
| 有文档且合理 → | 维度4（平台适配合理性） |

### 维度内扣分规则

| 问题等级 | 扣分 |
|----------|------|
| 致命问题 | -15 分/处 |
| 严重问题 | -12 分/处 |
| 中等问题 | -8 分/处 |
| 轻微问题 | -3 分/处 |

```
维度实际扣分 = min(扣分上限, 致命扣分 + 严重扣分 + 中等扣分 + 轻微扣分)

归零检查：
- 致命问题累计 ≥ 4 个 → 最终分 = 0
- 致命问题 ≥ 3 个 + 严重问题 ≥ 2 个 → 最终分 = 0
- 累计扣分超过 60 分 → 最终分 = 0
- 无鸿蒙代码或全部 Stub → 最终分 = 0

最终分 = max(0, 100 - 各维度实际扣分之和)
```

## 7. 扣分维度标注规则

所有检视表格的扣分列，必须在分数后标注维度编号，格式为 **`-X（维度N）`**：

| 检查项标签 | 对应维度 |
|------------|----------|
| ①契约一致性检查项 | 维度1（API 契约一致性） |
| ②平台实现差异检查项（主映射逻辑、函数行为） | 维度2（平台实现一致性） |
| ③架构桥接一致性检查项 | 维度3（RN 架构一致性） |
| 副作用&关联影响：**条件路由** | 无文档/不合理→维度2，有文档且合理→维度4 |
| 非 rawProps 属性默认值：**条件路由** | 无文档/不合理→维度2，有文档且合理→维度4 |
| 平台差异记录：合理差异→维度4，不合理差异→维度2 | |

示例：`-15（维度2）`、`-3（维度4）`、`-8（维度1）`

---

## 8. 评分格式要求

报告必须包含 `**综合评分：XX/100**`（粗体标记，中文冒号），确保 `_parseRNLibraryScore` 函数的 `/\*?\*?综合评分[：:\s]*(\d{1,3})\s*\/\s*100/i` 正则匹配。

评分正则匹配优先级为 `综合评分` > `总体评分/评分` > `得分`。
