# RN 一致性检视清单

本文档列出 RN 三方库鸿蒙化代码一致性检视的详细检查项，供检视人员参考。

> ⚠️ **核心定位**：本清单**仅检查鸿蒙化实现代码与上游 RN 原库 Android/iOS 原生模块的一致性**，不关注非鸿蒙化部分。

---

## 0. 代码定位与范围识别

### 0.1 鸿蒙化代码定位

| 检查项 | 检查内容 | 结果判定 | 处理方式 |
|--------|----------|----------|----------|
| `source/ohos/` 目录存在性 | 是否存在鸿蒙化目录 | 不存在 → 搜索其他位置 | 智能搜索定位 |
| `*.ets` 文件 | ArkTS/ETS 代码文件 | 无 → 搜索 @ohos 特征 | 代码特征搜索 |
| `@ohos.*` 导入 | 鸿蒙 API 调用 | 无 → 搜索 napi_ | NAPI 层搜索 |
| `napi_*` 函数 | C++ Native 绑定 | 无 → 无鸿蒙化代码 | 评分 0 分 |

### 0.2 上游原库代码定位

| 检查项 | 检查内容 | 结果判定 | 处理方式 |
|--------|----------|----------|----------|
| `source/RN/android/` 目录 | Android 原生模块 | 不存在 → 标注 | "缺少 Android 参考实现" |
| `source/RN/ios/` 目录 | iOS 原生模块 | 不存在 → 标注 | "缺少 iOS 参考实现" |
| `source/RN/src/` 目录 | JS/TS 接口定义 | 不存在 → 检查根目录 | 搜索 NativeModules 引用 |
| TurboModule Spec | Codegen 生成的接口定义 | 不存在 → 检查旧架构 | 检查 NativeModules 模式 |

## 1. API 契约一致性检查

### 1.1 方法签名一致性（15分）

| 检查项 | 对比对象 | 扣分规则 | 致命度 |
|--------|----------|----------|--------|
| 方法名匹配 | JS Spec / NativeModules 方法名 vs OHOS 方法名 | 不匹配扣 5 分 | 中等 |
| 参数数量匹配 | JS 调用参数数量 vs OHOS 接收参数数量 | **不匹配扣 8 分** | 致命 |
| 参数顺序一致 | 参数位置是否完全对应 | 顺序错误扣 6 分 | 严重 |
| 方法存在性 | JS 接口方法是否在 OHOS 实现 | **缺失扣 10 分** | 致命 |
| Stub 方法检测 | OHOS 方法是否返回固定值无操作 | **Stub 扣 8 分** | 致命 |
| 错误返回检测 | OHOS 方法是否返回错误而非实现 | **返回错误扣 10 分** | 致命 |

### 1.2 参数类型一致性（20分）⚠️ 最易出错维度

| 检查项 | JS/Android 类型 | OHOS 解析类型 | 扣分规则 | 致命度 |
|--------|----------------|-------------|----------|--------|
| boolean 解析 | boolean/bool | boolean | **解析为 string 扣 15 分** | 致命 |
| number 解析 | number/int/double | number | 精度丢失扣 5 分 | 中等 |
| string 解析 | string/String | string | 编码问题扣 2 分 | 轻微 |
| Array 解析 | Array<T>/List<T> | Array<T> | 元素类型不一致扣 8 分 | 严重 |
| Object 解析 | Object/Map/ReadableMap | Record/Object | 键值类型不一致扣 8 分 | 严重 |
| 空值处理 | T \| null / T? | T \| null | 不处理 null 扣 8 分 | 严重 |

**致命类型错误示例**：

```typescript
// ❌ 致命：boolean 被解析为 string
// JS Spec: startScan({force: boolean})
// OHOS:
const force = call.arguments['force'] as string;
// 结果：string "false" 在条件判断中仍为 truthy，功能完全失效！

// ✅ 正确：
const force = call.arguments['force'] as boolean;
```

### 1.4 事件/回调一致性（10分）
