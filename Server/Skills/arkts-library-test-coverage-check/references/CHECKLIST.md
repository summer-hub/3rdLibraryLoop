# ArktsLibraryTestCoverageCheckSkill 详细检查清单

本文件为 SKILL.md 中各维度的详细检查项展开说明，供执行检视时逐项对照。

---

## 维度 1：公开接口覆盖率（TC-01~TC-05）

### TC-01 核心接口未覆盖（Critical，-15 分）

**定义**：公开核心功能接口（标注为必须/required）无任何测试用例。

**检查方法**：
1. 从 `接口规格说明.md` 提取所有标注为 required/必须 的公开接口
2. 扫描所有测试文件，查找对这些接口的直接调用或间接测试
3. 核心接口包括但不限于：
   - 库的主入口方法
   - 文档标注为必须的功能
   - README 中列为核心功能的接口

**判定标准**：
- ✅ 有至少一个测试函数直接测试该接口 → 已覆盖
- ⚠️ 仅在其他测试中间接调用但未专门测试 → 需评估
- ❌ 无任何测试函数涉及该接口 → 未覆盖

> **归零规则 6 关联**：当 DEMO 目录和 test 目录均未对全部公开接口实现 100% 覆盖时，触发归零规则 6，综合评分直接为 0 分。只要 DEMO 或 test 目录中任意一个达到 100% 接口覆盖，即不触发此归零规则。

### TC-02 重要接口未覆盖（Major，-10 分）

**定义**：重要公开接口缺少测试用例（非核心但影响主要功能流程）。

**检查方法**：同 TC-01，但针对文档标注为推荐/可选的重要接口。

### TC-03 边界场景缺失（Major，-8 分）

**定义**：有测试的接口但缺少边界值/异常输入测试。

**典型缺失场景**：
- 数值参数：缺少极大值、极小值、零值、负值测试
- 字符串参数：缺少空字符串、超长字符串、特殊字符测试
- 数组参数：缺少空数组、超大数组测试
- 对象参数：缺少 null、空对象、缺失字段测试
- Promise 返回：缺少 reject 场景测试

### TC-04 可选接口未覆盖（Minor，-3 分）

**定义**：可选功能接口（标注为 optional）未测试。

### TC-05 接口参数组合未覆盖（Major，-5 分）

**定义**：接口有多参数时，仅测试了部分参数组合，缺少全组合覆盖。

---

## 归零规则 6 详细说明：接口覆盖率 100% 要求

**触发条件**：DEMO 目录和 test 目录的公开接口覆盖率**均未达到 100%**。

**不触发条件**（满足其一即可）：
- DEMO 目录（`demo/`、`example/`、`sample/` 等）中的代码调用了全部公开接口 → DEMO 覆盖率 100%
- test 目录（`test/`、`tests/`、`__tests__/`、`ohosTest/` 等）中的测试覆盖了全部公开接口 → test 覆盖率 100%

**计算方法**：
1. 从 `接口规格说明.md` 提取全部公开接口列表（设为 N 个）
2. 扫描 DEMO 目录，统计其中调用的公开接口数（D 个），DEMO 覆盖率 = D/N × 100%
3. 扫描 test 目录，统计其中覆盖的公开接口数（T 个），test 覆盖率 = T/N × 100%
4. 若 max(DEMO覆盖率, test覆盖率) = 100%，则不触发归零；否则触发

**注意**：此归零规则叠加于维度扣分之上，即使维度扣分后仍有剩余分数，只要触发此规则，综合评分直接为 0 分。

## 维度 2：测试质量（TC-06~TC-11）

### TC-06 断言缺失（Critical，-10 分）

**定义**：测试函数中无任何 assert/expect 断言语句。

**检查方法**：
1. 逐个扫描测试函数体
2. 查找 `assert*`、`expect*`、`chai.expect`、`should.*` 等断言调用
3. 仅包含 `console.log` 而无断言的测试视为断言缺失

**判定标准**：
- ✅ 有至少一个非空断言 → 通过
- ❌ 无任何断言或仅有 `console.log` → 断言缺失

### TC-07 断言过弱（Minor，-5 分）

**定义**：测试仅有断言"不抛异常"，未验证正确输出。

**典型模式**：
```typescript
// ❌ 断言过弱
it('should work', () => {
  expect(() => myFunction()).not.toThrow(); // 仅验证不抛异常
});

// ✅ 正确断言
it('should work', () => {
  const result = myFunction();
  expect(result).toBe(expectedValue); // 验证输出
});
```

### TC-08 测试独立性（Major，-8 分）

**定义**：测试间存在数据依赖，无法独立运行。

**典型问题**：
- 测试 A 修改全局状态，测试 B 依赖该状态
- 测试使用共享 mock 数据且未在 afterEach 中清理
- 测试顺序影响结果（换顺序就失败）

### TC-09 Mock 过度（Minor，-5 分）

**定义**：测试中 Mock 占比过高，导致测试脱离真实环境。

**判定标准**：
- Mock 数量 > 被测代码调用数的 50% → Mock 过度
- 关键鸿蒙 API 全部 Mock → Mock 过度
- 自身逻辑内部方法也被 Mock → Mock 过度

### TC-10 负面测试缺失（Major，-8 分）

**定义**：缺少异常/失败场景测试。

**应覆盖的负面场景**：
- 输入参数为 null/undefined/非法值
- 网络请求失败
- 权限不足
- 资源不可用

### TC-11 测试数据硬编码（Minor，-3 分）

**定义**：测试数据全硬编码，未提取为 fixtures/常量/工厂函数。

## 维度 3：鸿蒙化特性测试覆盖（TC-12~TC-17）

### TC-12 鸿蒙 API 调用未测试（Critical，-12 分）

**定义**：源码中调用的 @ohos.* API 在测试中无覆盖。

**检查方法**：
1. 在源码中扫描所有 `import from '@ohos.*'` 和直接调用 `@ohos.*` 的位置
2. 在测试文件中查找对应 API 的测试覆盖
3. 每个使用的 @ohos API 应有至少一个测试

**关键鸿蒙 API 类别**：
- 系统服务：@ohos.bluetooth、@ohos.network 等
- UI 框架：@ohos.arkui.* 等
- 存储：@ohos.data.* 等
- 设备：@ohos.deviceInfo 等

### TC-13 权限场景未测试（Major，-8 分）

**定义**：需权限的 API 无权限授予/拒绝场景测试。

### TC-14 Lifecycle 测试缺失（Major，-10 分）

**定义**：ArkTS 组件生命周期方法无测试覆盖。

**应覆盖的生命周期**：
- aboutToAppear / aboutToDisappear
- onPageShow / onPageHide
- onBackPress
- onActive / onInactive

### TC-15 NAPI 测试缺失（Major，-10 分）

**定义**：Native 模块通过 NAPI 暴露的接口无测试覆盖。

**检查方法**：
1. 找到所有 `napi_define_class` / `napi_define_properties` 暴露的方法
2. 在测试中查找对这些方法的调用测试

### TC-16 跨设备场景未测试（Minor，-5 分）

**定义**：鸿蒙多设备/分布式场景无测试。

### TC-17 鸿蒙配置测试缺失（Minor，-3 分）

**定义**：module.json5 中的关键配置（权限、设备类型等）未在测试中验证。

## 维度 4：测试分类覆盖（TC-18~TC-22）

### TC-18 缺少单元测试（Major，-8 分）

**定义**：对独立函数/方法无单元级测试（测试最小功能单元）。

**判定标准**：
- 检查是否有针对单个方法/函数的独立测试
- 单元测试应不依赖外部系统或 Mock 较少

### TC-19 缺少集成测试（Minor，-5 分）

**定义**：对模块间交互无集成级测试。

### TC-20 缺少端到端测试（Minor，-5 分）

**定义**：对完整功能流程无 E2E 测试（从用户视角验证完整链路）。

### TC-21 测试命名不规范（Minor，-3 分）

**定义**：测试文件/函数命名不符合规范。

**命名规范**：
- 测试文件必须包含 test/Test/spec 关键词
- 测试函数描述应清晰表达测试意图
- 建议格式：`it('should {预期行为} when {条件}')`

### TC-22 测试分类标注缺失（Minor，-2 分）

**定义**：测试未标注类型（unit/integration/e2e）。

---

## 维度 5：测试基础设施（TC-23~TC-26）

### TC-23 测试框架配置缺失（Major，-5 分）

**定义**：缺少鸿蒙测试框架配置。

**检查项**：
- 是否存在 @ohos/hypium 依赖配置
- 是否有测试运行配置文件
- oh-package.json5 中是否声明测试依赖

### TC-24 测试脚本缺失（Minor，-3 分）

**定义**：无测试运行脚本（如 hvigorw test 或自定义脚本）。

### TC-25 CI 集成缺失（Minor，-3 分）

**定义**：无 CI/CD 测试流程配置（如 .github/workflows 或 CI 脚本）。

### TC-26 测试数据管理缺失（Minor，-2 分）

**定义**：缺少测试数据/fixtures 的统一管理。

---

## 归零规则检查要点

1. **核心接口完全无测试**：逐一确认所有 required 接口均无测试 → 触发归零规则 1
2. **覆盖率 < 10%**：计算覆盖率后判定 → 触发归零规则 2
3. **无测试文件**：扫描结果为空 → 触发归零规则 3
4. **未发现鸿蒙化代码**：Phase 1 扫描无结果 → 触发归零规则 4
5. **源码不可访问**：目录不存在或无权限 → 触发归零规则 5
