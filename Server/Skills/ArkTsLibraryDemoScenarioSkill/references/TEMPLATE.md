# 测试 Demo 描述文档模板

本文件提供生成输出文档时使用的标准模板结构，可直接复制并填入真实内容。

---

## 输出文档模板

```markdown
# {库名} 测试 Demo 描述文档

## 概述

本文档基于 `{库名}` 库的接口规格说明文档（`{规格文档文件名}`）自动生成，
提供各接口的 ArkTS 测试 Demo 描述，供开发者参考实现功能验证 Demo 页面。

> 文档基于接口规格文档真实内容生成，所有接口名称、参数类型与规格文档保持一致。

## Demo 总览

| Demo 数量 | 覆盖接口数量 | 生成日期 |
|----------|------------|---------|
| {N} 个    | {M} 个      | {YYYY-MM-DD} |

## 测试 Demo 描述列表

| 序号 | 测试 Demo 名称 | 测试 Demo 描述 | 测试 Demo 步骤 | 测试 Demo 预期结果 | 对应函数接口 |
|-----|--------------|--------------|--------------|-----------------|------------|
| 1 | {Demo名称1} | {Demo描述1} | {步骤1} | {预期结果1} | {接口列表1} |
| 2 | {Demo名称2} | {Demo描述2} | {步骤2} | {预期结果2} | {接口列表2} |

## 接口覆盖矩阵

| 序号 | 接口名称 | 所在 Demo | 覆盖状态 |
|-----|---------|----------|---------|
| 1 | `{接口签名}` | {Demo名称} | ✅ 已覆盖 |
```

---

## 各字段填写规范

### 测试 Demo 名称

**格式**：`[功能动词/名词][操作对象][可选场景描述]Demo`

**命名示例：**

| 场景 | 推荐名称 |
|-----|---------|
| 单一核心功能 | `图片压缩处理Demo` |
| 生命周期管理 | `实例创建与销毁Demo` |
| 配置类接口 | `参数配置与验证Demo` |
| 异步操作 | `异步数据加载Demo` |
| 错误处理 | `异常捕获与恢复Demo` |
| 多接口组合 | `完整处理流程Demo` |

**注意：**
- 不超过 20 字
- 避免使用泛化词语（如"基础Demo"、"测试Demo"）
- 名称应能让开发者直接判断 Demo 的核心目的

---

### 测试 Demo 描述

**模板：**

```
{Demo名称}展示了如何使用 {接口名称} 实现 {功能描述}。
通过本 Demo，开发者可以了解 {接口的核心用法/参数含义/返回值处理方式}。
[可选：本 Demo 同时涵盖 {其他关联接口}，展示 {它们之间的调用关系/业务场景}。]
```

**示例：**

```
"本 Demo 展示 BlurManager 的完整生命周期管理流程，包括构造（传入 radius 参数）、
动态更新 radius 属性（setRadius/getRadius 读写）及最终资源释放（release）。
帮助开发者理解 BlurManager 实例从创建到销毁的正确使用方式，以及 radius 属性的读写一致性。"
```

---

### 测试 Demo 步骤

**步骤结构模板：**

```
1. 创建 Demo 页面，添加 [UI组件列表：按钮、输入框、展示区、日志区等]。
2. [用户操作]，触发 `{接口名称}({参数示例})` 调用。
3. 将接口返回值 / 状态变化展示在 [展示区域名称]。
4. [下一步操作，如有]，验证 [具体行为]。
[可选] 5. 对比 / 补充验证步骤。
```

**步骤描述规范：**

| 维度 | 要求 | 示例 |
|-----|-----|-----|
| 页面构建 | 说明需要哪些 UI 组件 | "添加 radius 输入框、'执行'按钮和图片显示区域" |
| 交互触发 | 明确用户操作和调用时机 | "点击'执行'按钮，调用 `blur(pixelMap)`" |
| 参数传递 | 说明传入参数来源/示例值 | "传入 radius=15，pixelMap 为图库选取的图片" |
| 结果展示 | 说明如何在页面显示结果 | "将返回的 PixelMap 显示在结果区域" |
| 验证方式 | 说明如何判断成功 | "确认图片宽高与原图一致，视觉出现模糊效果" |

---

### 测试 Demo 预期结果

**模板：**

```
1. [页面/UI 状态]：{可观测的界面变化描述}。
2. [接口返回值]：{返回值类型/内容/范围} 符合预期。
3. [功能效果]：{功能方面的可验证效果}。
4. [异常/边界]：{无异常抛出 / 错误码正确返回}。
[可选] 5. [性能]：{操作耗时在合理范围内}。
```

**预期结果描述规范：**
- 必须可观测（能在 Demo 页面上直接看到或测量）
- 必须具体（避免"正确返回"这样的模糊描述）
- 推荐包含数值范围（如尺寸不变、耗时 < N秒）
- 必须包含"无异常/无崩溃"验证项

**示例：**

```
1. 点击"执行异步模糊"后，按钮立即变为禁用状态，Loading 指示器出现，表明异步任务已启动。
2. `blur()` 返回的 Promise 正常 resolve，Loading 消失，模糊后图片正确显示在结果区域。
3. 模糊后图片的宽高像素数与原图完全一致，视觉效果出现模糊。
4. UI 主线程在等待期间不冻结（可正常操作页面其他控件）。
5. 无 Promise reject 或未捕获异常；页面日志显示耗时。
```

### 对应函数接口

**格式**：每行一个接口，使用代码格式（反引号），包含完整函数签名。

```
`functionName(paramName: ParamType): ReturnType`
`ClassName.methodName(param: Type): ReturnType`
`new ClassName(param: Type)`
`CONSTANT_NAME: Type`（常量）
`InterfaceName`（接口类型，仅被其他接口用作参数/返回值时列出）
```

## 接口分组决策树

使用以下决策树判断接口是否应合并到同一 Demo：

```
接口 A 和接口 B 是否应合并？
│
├─ A 的返回值是 B 的入参？ ──→ 是 ──→ 合并
│
├─ A 和 B 共同完成一个完整业务场景？ ──→ 是 ──→ 合并
│   （如: init + execute + cleanup）
│
├─ A 和 B 都属于同一对象的状态读写？ ──→ 是 ──→ 合并
│   （如: setter + getter）
│
├─ A 不调用 B，B 不调用 A，功能方向不同？ ──→ 是 ──→ 分开
│
└─ 默认：分开（每个接口独立 Demo）
```

## 常见接口模式与推荐 Demo 封装方式

| 接口模式 | 推荐 Demo 封装 |
|---------|--------------|
| `constructor + method + release` | 封装为"完整生命周期 Demo" |
| `async` 方法（返回 Promise） | 独立 Demo，展示异步等待与结果处理 |
| `sync` 方法 | 独立 Demo，或与对应 async 方法对比展示 |
| `getter + setter` 一对 | 合并为"属性读写 Demo" |
| `init + execute` 依赖链 | 合并为"初始化与执行 Demo" |
| 多个枚举值影响同一方法行为 | 在同一 Demo 中用选择器切换枚举值展示 |
| 错误码返回的接口 | 在对应 Demo 中增加"异常输入"验证步骤 |
