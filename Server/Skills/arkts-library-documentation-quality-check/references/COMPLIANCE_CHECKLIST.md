# 文档质量检视合规检查清单

> 检视完成后，对照本清单确认报告完整性与格式合规性，确保后端可自动解析。

---

## 1. 检视范围检查

| # | 检查项 | 通过条件 |
|---|--------|----------|
| 1.1 | 文档全量扫描 | 已扫描所有 README、.md、.txt、.rst、CHANGELOG、.json5 文件 |
| 1.2 | 源码扫描 | 已扫描所有 .ets/.ts 文件（排除 node_modules） |
| 1.3 | 鸿蒙化说明定位 | 已通过三级优先级搜索定位鸿蒙化说明文档 |
| 1.4 | 接口规格对照 | 已读取 `接口规格说明.md` 并提取公开接口列表 |
| 1.5 | 文档分类映射 | 已按类别归类（入口/API/鸿蒙化/构建配置/导出声明/示例/代码注释） |

---

## 2. 五维度检视检查

| # | 维度 | 通过条件 |
|---|------|----------|
| 2.1 | 文档完整性 | 已检查 README、鸿蒙化说明、API 文档、安装指南、使用示例、中文文档 |
| 2.2 | 文档准确性 | 已核对 API 签名、示例代码可运行性、导出声明一致性、废弃 API |
| 2.3 | 文档易读性 | 已检查结构、目录导航、语言、图表、格式规范 |
| 2.4 | 代码级文档质量 | 已检查 JSDoc/TSDoc 覆盖、参数/返回值描述、鸿蒙特有 API 注释 |
| 2.5 | 鸿蒙化文档专项 | 已检查权限说明、构建配置、差异对比、迁移指南、兼容性说明 |

## 3. 评分计算检查

| # | 检查项 | 通过条件 |
|---|--------|----------|
| 3.1 | 维度子评分 | 每个维度独立计算 `max(0, 100 - Critical×15 - Major×8 - Minor×3)` |
| 3.2 | 综合评分 | 按权重加权：30/25/15/10/20 |
| 3.3 | 严苛保障 | ≥3 Critical → 最高60分；≥1 Critical + ≥5 Major → 最高50分 |
| 3.4 | 等级标注 | 已按 90-100/80-89/70-79/60-69/50-59/<50 标注等级 |

---

## 4. 报告格式检查（后端解析依赖）

| # | 检查项 | 通过条件 |
|---|--------|----------|
| 4.1 | 综合评分行 | `**综合评分：数字/100**`，中文全角冒号 `：`，位于"二、综合评分"首行 |
| 4.2 | 维度评分明细表 | 紧随综合评分之后展示 |
| 4.3 | 维度子评分标注 | 每个维度详情末尾标注 `> {维度}子评分：{分数}/100` |
| 4.4 | 问题清单 | 包含文档/文件、严重度、维度、描述、修复建议 |
| 4.5 | 改进建议 | 提供可执行的改进建议 |

## 5. 常见遗漏检查

| # | 检查项 | 说明 |
|---|--------|------|
| 5.1 | 示例代码可运行性 | 导入路径错误是最常见 Critical，务必逐个验证 |
| 5.2 | 权限说明 | 使用 @ohos.network 等系统 API 必须检查权限说明 |
| 5.3 | 双 README 同步 | README_zh.md 与 README.md 需双向检查 |
| 5.4 | 隐含行为文档化 | 生命周期自动 API 调用（如 aboutToDisappear → destroy()） |
| 5.5 | oh-package.json5 解析 | 允许注释和尾逗号，不能按严格 JSON 解析 |
