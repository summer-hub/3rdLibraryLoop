# 知识库查询指南

> 本文档说明在文档质量检视过程中，如何查询鸿蒙知识库补充检查标准，提升检视的准确性和完整性。

---

## 1. 何时查询知识库

| 场景 | 是否查询 |
|------|----------|
| 通用文档格式规范（Markdown 语法） | ❌ 不需要 |
| 鸿蒙 API 文档标准（@ohos.* 文档要求） | ✅ 需要 |
| ArkTS JSDoc 注释规范 | ✅ 需要 |
| 鸿蒙权限说明标准 | ✅ 需要 |
| 鸿蒙化差异对比文档要求 | ✅ 需要 |
| 鸿蒙设备兼容性说明 | ✅ 需要 |

**判断原则**：当不确定鸿蒙特有的文档规范或最佳实践时，查询知识库。

---

## 2. 查询流程

### 2.1 构建检索词

从文档检视需求中提取关键词，组合检索词：

**提取维度**：
- 技术栈：ArkTS、OpenHarmony、HarmonyOS、ArkUI
- 文档类型：API 文档、JSDoc、README、CHANGELOG
- 鸿蒙专项：权限说明、差异对比、迁移指南、兼容性

**组合示例**：
```
需求：检查鸿蒙化库的 @ohos.* API 文档完整性
检索词：["@ohos 文档规范", "HarmonyOS API 文档要求", "ArkTS JSDoc 规范"]
```

### 2.2 调用知识库工具

调用 `kb-server_` 前缀的知识检索工具（具体工具名通过 `gateway_list_tools` 获取，参见 [MCP 能力检索指南](MCP_TOOL_DISCOVERY.md)）。

**调用策略**：
- 一次查询一个关键词
- 若返回不相关，调整关键词重试（最多3轮）
- 记录查询过的关键词，避免重复

### 2.3 结果处理

对知识库返回的内容分类处理：

| 内容类型 | 处理方式 | 放置位置 |
|----------|----------|----------|
| 文档检查清单 | 整合为检查项 | references/ 的检查文档 |
| 代码注释规范示例 | 提取关键模式 | 评分时的参考标准 |
| 鸿蒙文档最佳实践 | 精简引用 | SKILL.md body 对应 Phase |
| 注意事项 | 精简引用 | SKILL.md body 或 references/ |
| 常见文档缺失项 | 记录为检查项 | CHECK_DIMENSIONS.md 补充 |

---

## 3. 知识融合原则

### 3.1 不照搬全文

知识库返回的内容可能很长，**不要**完整复制到检视标准中。应：
- 提取核心要点
- 精简为 1-3 句话引用
- 详细内容放入 references/，SKILL.md 中用链接引用

### 3.2 标注来源

在引用知识库内容时，标注来源：

```markdown
> 📖 来源：鸿蒙知识库，关键词"ArkTS 文档规范"
```

### 3.3 验证适用性

知识库返回的内容需验证是否适用于文档检视场景：
- API 版本是否匹配（API 12+ vs 更低版本）
- 场景是否匹配（三方库文档 vs 系统应用文档）
- 规范是否仍然有效

---

## 4. 常见文档检视知识库查询场景

### 4.1 鸿蒙 JSDoc/TSDoc 规范

检索词建议：
- `ArkTS JSDoc 规范` — 注释格式要求
- `@ohos API 文档要求` — 系统 API 文档标准
- `ArkTS 注释最佳实践` — 注释编写指南

### 4.2 鸿蒙权限文档

检索词建议：
- `HarmonyOS 权限说明` — 权限声明文档标准
- `@ohos 权限列表` — 系统 API 权限映射

### 4.3 鸿蒙化文档差异

检索词建议：
- `鸿蒙化适配文档` — 适配说明文档要求
- `HarmonyOS 迁移指南` — 迁移文档标准
- `OpenHarmony 兼容性说明` — 兼容性文档要求
