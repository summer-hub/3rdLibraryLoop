# 文档质量检视报告模板

本文件定义 `rn-library-documentation-quality-check` 技能生成的检视报告的标准格式。

> ⚠️ 报告必须包含 `**综合评分：XX/100**` 格式，且评分值位于"二、综合评分"章节，确保可被 `_parseRNLibraryScore` 函数正确解析。

---

## 一、报告结构

报告文件名：`文档质量检视报告.md`，保存到 `{outputDir}` 目录。

报告包含六个章节：

1. 检视概览
2. 综合评分
3. 各维度评分明细
4. 检视维度详情
5. 问题清单
6. 改进建议

---

## 三、评分解析兼容性

报告中的评分格式必须兼容 `_parseRNLibraryScore` 函数的正则匹配：

```
评分正则匹配优先级：
1. **综合评分：XX/100**（最高优先级，本 SKILL 使用）
2. 总体评分/评分：XX
3. 得分：XX
```

**关键格式要求**：
- 评分必须使用 `**综合评分：XX/100**` 格式（加粗 + 冒号 + 分数/100）
- 评分必须位于"二、综合评分"章节
- 分数为 0-100 的整数

## 四、各维度扣分计算示例

### 示例 1：API 文档完整性

```
检查发现：
- AD-001 (Critical): 2 个 export 接口无注释 → -8 × 2 = -16
- TG-001 (Major): 3 个方法缺少 @param → -4 × 3 = -12
- TG-005 (Minor): 5 个方法缺少 @since → -1 × 5 = -5

维度扣分 = min(-20, -16 + (-12) + (-5)) = min(-20, -33) = -20
维度得分 = 20 + (-20) = 0
```

### 示例 2：文档与接口规格交叉验证

```
检查发现：
- XC-003 (Critical): 1 个文档描述的 API 在接口规格中不存在 → -8
- XC-002 (Major): 3 个接口规格中定义的 API 在用户文档中无描述 → -4 × 3 = -12
- XC-005 (Major): 2 个方法返回类型不一致 → -4 × 2 = -8
- XC-008 (Critical): 1 个缺失接口仍标记为支持 → -8
- XC-007 (Minor): 1 个参数可选性不一致 → -1

维度扣分 = min(-15, -8 + (-12) + (-8) + (-8) + (-1)) = min(-15, -37) = -15
维度得分 = 15 + (-15) = 0
```

### 示例 3：代码仓基础信息

```
检查发现：
- RM-004 (Major): 基础章节不完整（缺少约束与限制章节） → -4
- RM-007 (Minor): keywords 缺少鸿蒙相关关键词 → -1

维度扣分 = min(-15, -4 + (-1)) = -5
维度得分 = 15 + (-5) = 10
```

### 示例 4：综合评分计算

```
各维度扣分：
- API 文档完整性: -20
- 鸿蒙化适配说明: -20
- 代码仓基础信息: -5
- 代码示例质量: -8
- 变更记录与版本规范: -4
- 文档与代码交叉验证: -15
- 文档准确性与国际化: -1

归零检查：文档非完全空白，核心 API 有部分注释 → 不触发归零

最终分 = max(0, 100 - 20 - 20 - 5 - 8 - 4 - 15 - 1) = max(0, 27) = 27
评分等级：极差
```

### 示例 4：跳转文档模式评分

```
仓库：rntpc_react-native-network-info
文档模式：跳转文档

检视发现：
- API 文档完整性:
  - DT-001 (Major): TurboModule Spec 接口缺少注释 → -4
  - Minor: 2 个方法缺少 @since → -1 × 2 = -2
  - 维度扣分 = min(-25, -4 + (-2)) = -6

- 鸿蒙化适配说明:
  - HA-019 (Major): 外部文档约束与限制不完整 → -4
  - HA-023 (Minor): 遗留问题章节为空 → -1
  - 维度扣分 = min(-25, -4 + (-1)) = -5

- 代码仓基础信息:
  - RM-003 (Minor): 缺少 README_zh.md（中文文档） → -1
  - 注意：README 极简是跳转模式设计，不记录 RM-002/RM-004
  - 维度扣分 = min(-15, -1) = -1

- 代码示例质量:
  - 外部文档有完整示例，但示例未展示错误处理 → EX-007 Minor → -1
  - 维度扣分 = min(-15, -1) = -1

- 变更记录与版本规范:
  - CL-001 (Major): 缺少 CHANGELOG.md → -4
  - 维度扣分 = min(-10, -4) = -4

- 文档准确性与国际化:
  - XC-012 (Major): 外部文档版本号与 package.json 不一致 → -4
  - 维度扣分 = min(-5, -4) = -4

最终分 = max(0, 100 - 6 - 5 - 1 - 1 - 4 - 4) = max(0, 79) = 79
评分等级：一般

注意与内嵌模式的差异：
- 跳转模式下 README 维度扣分较少（极简是设计选择不是缺陷）
- 但外部文档的完整性、与本地代码的一致性成为重点检视对象
- CHANGELOG 缺失等本地文件问题仍需独立计算
```
