# 规则检视指南

> 本文档为 Phase 3「逐条规则检视」的详细操作指南，覆盖规则文件读取、源码对照检查、判定规则、few-shot 参考四个环节。

---

## 1. 规则文件结构

读取 `rules/R-XX-*.md`，获取以下字段：

| 字段 | 用途 |
|------|------|
| **状态** | `draft` / `active`。只消费 `active` 状态规则（见 SKILL.md 核心定位 #3） |
| **严重级别** | high / medium / low，及判定依据 |
| **适用范围** | 含预筛特征（Phase 2 使用） |
| **问题本质** | 机制层描述，理解这类问题为什么会发生 |
| **检查点** | 逐条可判定的源码检查动作（2-5 条） |
| **错误特征** | 命中此类问题的典型代码形态 |
| **正确特征** | 修复后的代码形态 |
| **来源案例** | 案例索引（编号/库/现象/案例文件） |

---

## 2. 对照源码检查

按规则文件的**检查点**逐条对照 `{outputDir}/source/ohos/` 源码检查。

### 2.1 检查点判定

每条检查点给出 **是/否/疑似** 判定：

| 判定 | 含义 | 处理 |
|------|------|------|
| **是**（命中） | 源码存在规则描述的**错误特征** | 记录为命中问题，引用案例作为修复指引 |
| **否**（通过） | 源码符合**正确特征** | 记录为通过 |
| **疑似** | 无法确定，需进一步确认 | 记录为疑似命中，报告中标注"需人工复核" |

### 2.2 检查点判定技巧

| 检查点类型 | 判定方法 |
|------------|----------|
| 存在性检查（是否存在某文件/某调用） | 全量扫描源码目录，grep 关键词 |
| 顺序检查（析构顺序/注册时序） | 阅读相关函数/析构函数，分析成员声明顺序与销毁顺序 |
| 完整性检查（接口是否全部实现） | 对照接口声明与实现文件，逐一核对 |
| 健壮性检查（异常处理/空判） | 阅读异常分支代码，检查 try-catch / null 判断 |

### 2.3 证据记录

命中检查点时，必须记录**证据**：
- 文件路径 + 行号（如 `ReanimatedModuleProxy.cpp:192-200`）
- 关键代码片段（≤15 行，用 `// ←` 标注缺陷点）
- 判定依据（为什么判定为命中）

> 证据是报告「命中问题详情」的核心内容，缺失证据的命中判定视为无效。

---

## 3. 规则命中判定

- 规则中**任一检查点命中错误特征** → 该规则**命中**（记 1 个问题）
- 所有检查点均通过 → 该规则**通过**
- 疑似命中 → 按命中处理（报告中标注"疑似"），避免漏报

---

## 4. few-shot 参考

判定困难时，读取规则文件引用的案例文件（`cases/KI-XXX-*.md`），对照"错误代码/正确代码"片段辅助判定。

### 4.1 案例文件结构

| 字段 | 用途 |
|------|------|
| 库与现象 | 原始具体信息 |
| 根因 | 机制层根因（与规则"问题本质"呼应） |
| 错误代码 | 修复前代码片段（`verified: diff` 时必填） |
| 正确代码 | 修复后代码片段（`verified: diff` 时必填） |
| 修复方式 | 可迁移的修复模式 |
| PR 链接 | 修复 PR 完整 URL |
| diff 材料 | 链接到 `pr-info/{repo}-{number}.md` |

### 4.2 使用场景

| 场景 | 用法 |
|------|------|
| 判定困难 | 对照案例错误/正确代码，确认当前库代码形态属于哪一类 |
| 修复指引 | 从案例「修复方式」提炼可迁移的修复建议 |
| 证据补充 | 案例 diff 材料可作为命中判定的佐证 |

---

## 5. 常见判定陷阱

| 陷阱 | 规避方法 |
|------|----------|
| 只看 ArkTS 层，忽略 C++ 层 | 同时检索 `.cpp` / `.h` 文件 |
| 只看 `source/ohos/`，忽略 `source/RN/` 对比 | 命中判定需与上游对比，确认是鸿蒙化引入的问题还是上游遗留 |
| 凭印象判定，不记录证据 | 每条命中必须记录文件路径 + 行号 + 代码片段 |
| 疑似命中直接跳过 | 疑似按命中处理，报告中标注"需人工复核" |
