# 预筛指南

> 本文档为 Phase 2「预筛适用规则」的详细操作指南。预筛是**核心环节**：知识库 19+ 条规则不可能全部适用于每个库，预筛决定哪些规则进入深度检查，直接影响检视效率与评分准确性。

---

## 1. 预筛特征四维度

对每条规则，读取其规则文件（`rules/R-XX-*.md`）的**适用范围 + 预筛特征**，从四个维度判定是否适用：

| 维度 | 判定依据 | 检索位置 |
|------|----------|----------|
| **依赖特征** | 当前库的 `oh-package.json5` / `package.json` 依赖中是否包含规则描述的依赖类型 | `{outputDir}/source/ohos/oh-package.json5`、`package.json` |
| **文件特征** | 源码中是否存在规则描述的文件类型（`.ets` / `.cpp` / `module.json5` 等） | `{outputDir}/source/ohos/` 全量文件扫描 |
| **API 特征** | 源码中是否调用规则描述的 API（`sensor.on` / `.gesture()` / `window` API 等） | `{outputDir}/source/ohos/` 代码内容检索 |
| **能力声明** | 接口规格说明.md / README 中是否声明规则描述的能力（全屏/横屏/传感器等） | `{outputDir}/接口规格说明.md`、README |

---

## 2. 判定规则

| 判定 | 条件 | 处理 |
|------|------|------|
| **适用** | 命中任一预筛特征 | 进入 Phase 3 深度检查 |
| **不适用** | 未命中任何预筛特征 | 跳过，记录跳过原因 |

> ⚠️ **预筛不适用规则不计入评分分母**。评分只基于「适用规则」计算。

---

## 3. 常见预筛误判与规避

### 3.1 误判为「适用」（过度预筛）

| 场景 | 规避方法 |
|------|----------|
| 库的 `example/` 目录含某能力，但库本体没有 | 预筛只看库本体源码，排除 `example/` |
| 依赖中声明了某 SDK，但代码从未调用 | 依赖特征需**结合 API 特征**确认，仅依赖声明不足以判定适用 |
| 上游 RN 原库有某能力，但鸿蒙化实现未移植 | 预筛针对**鸿蒙化实现**（`source/ohos/`），不看上游 `source/RN/` |

### 3.2 误判为「不适用」（漏筛）

| 场景 | 规避方法 |
|------|----------|
| 能力通过 C++ 层实现，ArkTS 层无痕迹 | 同时检索 `.cpp` / `.h` 文件中的 API 特征 |
| 能力声明在 README 但代码中命名不同 | 以「能力声明」维度兜底，README/接口文档声明即视为候选 |
| 规则描述的能力是「间接依赖」（如手势库被本库依赖） | 检查 `oh-package.json5` 的 dependencies 是否含相关库 |

### 3.3 判定技巧

- **先读 INDEX.md 分类**：媒体与窗口类规则（R-01/R-09/R-10）只对媒体/窗口类库可能适用；C++ 内存类规则（R-07/R-12）只对含 C++ 层的库可能适用。分类可快速缩小候选集。
- **能力声明优先**：接口规格说明.md 是预筛的最快入口，先读它了解库对外声明的能力，再对照规则分类。
- **记录跳过原因**：不适用规则必须记录具体原因（如「库无全屏/视频/Web 媒体能力声明，ArkTS 层无窗口状态 API」），供报告「不适用规则清单」使用。

---

## 4. 预筛输出

预筛完成后，输出两类清单：

1. **适用规则清单**：规则编号 + 规则名 + 命中预筛特征（进入 Phase 3）
2. **不适用规则清单**：规则编号 + 规则名 + 不适用原因（写入报告）

> 预筛结果示例参见 [报告模板](assets/REPORT_TEMPLATE.md) 的「二、规则命中清单」。
