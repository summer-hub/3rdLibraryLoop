# 覆盖率增量过滤指南

> 本文档说明如何解析 Demo 覆盖率报告（由 `rnoh-lib-demo-coverage` / `script_rn_analyze_demo_coverage` 生成），提取已覆盖接口，执行增量过滤。

---

## 1. 覆盖率报告结构

覆盖率报告为 Markdown 文件，章节用 `---` 水平线分隔，按以下顺序排列：

| 序号 | 章节标题 | 用途 |
|------|----------|------|
| 1 | `# {标题}` + 基本信息表 | 库名、源文件数、生成时间 |
| 2 | `## 覆盖率总览` | 方法级覆盖率百分比、S/N/M 统计、进度条 |
| 3 | `### 按接口类型统计` | method/property/function 等分类别覆盖率 |
| 4 | `## 类级覆盖率` | 按类分组的覆盖明细 |
| 5 | `## 未覆盖接口详情` | **核心**：未覆盖接口清单（含参数、返回类型） |
| 6 | `## 已覆盖接口详情` | **核心**：已覆盖接口清单（含签名、覆盖文件） |
| 7 | `## 文件覆盖详情` | 每个 Demo 文件覆盖的接口 |
| 8 | `## 覆盖率提升建议` | 未覆盖接口补充清单 |

> 增量过滤主要使用章节 5（未覆盖接口详情）和章节 6（已覆盖接口详情）。

---

## 2. 解析覆盖率总览

### 2.1 章节格式

```markdown
## 覆盖率总览

### 方法级覆盖率: {rate}% ({badge})

| 统计项 | 数量 |
|--------|------|
| 类/接口总数 (S) | {S} |
| 方法/属性总数 (N) | {N} |
| 已覆盖 (M) | {M} |
| 未覆盖 | {N - M} |

覆盖率进度: [████████████████░░░░] {rate}%
```

### 2.2 提取字段

| 字段 | 提取方式 | 示例值 |
|------|----------|--------|
| 覆盖率 | `### 方法级覆盖率: (\d+\.\d+)%` | `75.00` |
| 状态 | `### 方法级覆盖率: \d+\.\d+% \((.+)\)` | `中` |
| 类总数 S | `类/接口总数 \(S\) \| (\d+)` | `12` |
| 接口总数 N | `方法/属性总数 \(N\) \| (\d+)` | `45` |
| 已覆盖 M | `已覆盖 \(M\) \| (\d+)` | `30` |
| 未覆盖数 | `未覆盖 \| (\d+)` | `15` |

状态值仅四种：`高`(≥80%)、`中`(≥50%)、`低`(≥20%)、`极低`(<20%)。

## 3. 解析已覆盖接口详情

### 3.1 章节格式

```markdown
## 已覆盖接口详情

### {idx}. {className}

| # | 接口 | 类型 | 层级 | 签名 | 覆盖文件 |
|---|------|------|------|------|----------|
| 1 | `memberName` | method | - | `signature` | `file1.tsx`, `file2.tsx` |
```

- 按类名分组，每组一个 `###` 子标题
- 顶层导出接口的类名显示为 `(顶层)`
- 空情况：`*暂无已覆盖接口*`

### 3.2 提取已覆盖接口集合

从每行表格提取：

| 字段 | 提取方式 |
|------|----------|
| 类名 | `### \d+\. (.+)` |
| 接口名 | `\| \`(.+?)\` \|` （第一列，反引号包裹） |
| 类型 | 第二列（method/property/function/...） |
| 签名 | 第五列，反引号包裹，注意 `\|` 转义需还原为 `\|` |

构建 `coveredSet`：`{className}.{memberName}` 或仅 `memberName`（顶层导出）。

### 3.3 注意事项

- 表格单元格中的管道符 `|` 被转义为 `\|`，解析时需还原
- 覆盖文件列最多显示 3 个，超出部分用 ` +{N}` 表示
- 类型字段值：`method`、`constructor`、`property`、`field`、`enumValue`、`function`、`variable`、`type`

## 4. 解析未覆盖接口详情

### 4.1 章节格式

```markdown
## 未覆盖接口详情

### {idx}. {className} ({count} 个未覆盖)

| # | 接口 | 类型 | 层级 | 参数 | 返回类型 | 说明 |
|---|------|------|------|------|----------|------|
| 1 | `memberName` | method | - | id: string | Promise<void> | 断开连接 |
```

- 按类名分组，**组标题含未覆盖数量**：`### {idx}. {className} ({count} 个未覆盖)`
- 表格 7 列（比已覆盖多：参数、返回类型、说明；少：签名、覆盖文件）
- 空情况：`*所有接口均已覆盖！*`

### 4.2 提取未覆盖接口

从每行表格提取：

| 字段 | 提取方式 |
|------|----------|
| 类名 | `### \d+\. (.+?) \(\d+ 个未覆盖\)` |
| 接口名 | 第一列，反引号包裹 |
| 类型 | 第二列 |
| 参数 | 第五列（格式：`name?: type, name: type`） |
| 返回类型 | 第六列 |
| 说明 | 第七列 |

## 5. 增量过滤流程

### 5.1 整体流程

```
1. 读取覆盖率报告 Markdown 文件
2. 解析"覆盖率总览"→ 提取 S/N/M 统计
3. 解析"已覆盖接口详情"→ 构建 coveredSet
4. 解析"未覆盖接口详情"→ 构建 uncoveredList（含详细信息）
5. 将 uncoveredList 与接口规格 JSON 交叉验证：
   - 确认未覆盖接口在规格中存在
   - 补充规格中的平台标注
6. 对 uncoveredList 执行 HarmonyOS 平台过滤（Phase 4.2）
7. 最终得到待生成 Demo 的接口清单
```

### 5.2 交叉验证

覆盖率报告中的接口名需与 `interface-spec.json` 中的接口匹配：

| 匹配维度 | 说明 |
|----------|------|
| 类名匹配 | 报告中的 `className` 对应规格 JSON 中的类/模块名 |
| 接口名匹配 | 报告中的 `memberName` 对应规格 JSON 中的方法/属性名 |
| 签名一致性 | 报告中的签名应与规格 JSON 中的签名一致（参数、返回类型） |

> 若报告中接口在规格 JSON 中找不到匹配，以规格 JSON 为准（报告可能基于旧版规格）。

### 5.3 边界情况处理

| 情况 | 处理方式 |
|------|----------|
| 报告标注 `*所有接口均已覆盖！*` | 输出文档标注"所有接口已覆盖，无需生成新 Demo"，终止流程 |
| 报告标注 `*暂无已覆盖接口*` | 全部接口视为未覆盖，退化为全量模式 |
| 报告中接口在规格中不存在 | 以规格为准，忽略报告中该接口 |
| 规格中有接口但报告中没有 | 视为未覆盖，纳入待生成清单 |
| 报告文件格式异常无法解析 | 输出警告，退化为全量模式 |

## 6. 增量模式输出文档差异

增量模式下，输出文档的概述章节额外包含：

```markdown
## 概述

本文档基于 `{库名}` 库的接口规格和 Demo 覆盖率报告生成。

> **增量模式**：本文档仅针对 Demo 覆盖率报告中未覆盖的接口生成 Demo 描述。
>
> **覆盖率来源**：`{demoCoverage报告路径}`
> **接口统计**：总接口数 {N}，已覆盖 {M}，本次生成 {待生成数}

> **平台说明**：本文档仅包含 HarmonyOS 平台可用的测试 Demo。已过滤 iOS/Android 平台专用接口。
```

接口覆盖矩阵中仅列出本次生成的未覆盖接口，已覆盖接口不出现（或在备注中说明"已由现有 Demo 覆盖"）。

## 7. 报告章节分隔与解析技巧

### 7.1 章节分隔

报告各章节用 `---` 水平线分隔。解析时按 `^---$` 分割为章节块，每块以 `## ` 开头。

### 7.2 表格行解析

所有表格为标准 GitHub Markdown 格式，管道符 `|` 分隔。注意事项：

- 单元格内管道符被转义为 `\|`，解析时需还原
- 反引号包裹的字段：`接口`、`类名`、`签名`、`覆盖文件`，解析时去除反引号
- 表头行和分隔行（`|---|---|...`）需跳过

### 7.3 组标题解析

已覆盖接口的组标题：`### {idx}. {className}`（无数量后缀）
未覆盖接口的组标题：`### {idx}. {className} ({count} 个未覆盖)`（有数量后缀）

通过是否有 `个未覆盖` 后缀区分两种章节。
