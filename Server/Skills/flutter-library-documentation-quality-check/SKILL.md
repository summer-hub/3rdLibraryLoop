# FlutterLibraryDocumentationQualityCheckSkill

对 Flutter 三方库的**鸿蒙化代码相关文档**进行文档质量检视，评估鸿蒙化文档的完整性、准确性、易读性，特别关注鸿蒙化接口说明、三方库调用方式、Flutter版本对应关系等关键内容。

> ⚠️ **核心定位**：本 SKILL **仅检视鸿蒙化代码相关文档**，不关注非鸿蒙化部分的文档。检视核心是 README.OpenHarmony.md 等鸿蒙专属文档。**上游原始 README.md 不纳入鸿蒙化检视评分**——很多仓库的 README.md 是上游原始项目文档，鸿蒙化内容应正确放置在专属文档中，不因原始 README.md 缺少鸿蒙内容而扣分。通过**智能搜索识别鸿蒙化相关文档**，分析文档的完整性、准确性、易读性等方面。

---

## 任务参数

| 参数 | 必需 | 说明 |
|------|------|------|
| `repoUrl` | ✅ | Git 仓库地址，支持分支 `?branch=xxx` |
| `outputDir` | ✅ | 输出目录绝对路径，存放检视报告 |
| `interfaceDocPath` | ✅ | 接口规格说明文档路径（用于准确性交叉验证） |
| `repoName` | ✅ | 仓库名称（用于报告标识） |

---

## 输入依赖

本 SKILL 是 Flutter 仓库检视流程的**第六阶段**，依赖：

- **前置 SKILL**: `flutter-library-memory-leak-check`
- **输入文件**: `接口规格说明.md`、`内存泄露检视报告.md`
- **仓库源码**: 已克隆到 `{outputDir}/source/`

## 工作流程

### Phase 0：鸿蒙化相关文档智能定位

**通过多维度搜索策略**，智能识别鸿蒙化相关文档，而非检视所有文档。

#### 0.1 鸿蒙化文档搜索策略（优先级递减）

| 搜索维度 | 文件特征 | 权重 | 说明 |
|----------|----------|------|------|
| **鸿蒙专属文档** | `README.OpenHarmony.md`、`README.OpenHarmony_CN.md`、`README.openharmony.md`、`README.harmony.md`、`README.ohos.md` 及包级子目录同名文件 | ⭐⭐⭐⭐ 最高 | 鸿蒙化专属文档，是检视核心 |
| **README 鸿蒙章节** | 根/包 README.md 中包含 "ohos"、"harmony"、"openharmony"、"鸿蒙" 等关键词 | ⭐⭐⭐ 高 | 仅当**不存在鸿蒙专属文档时**才检视 |
| **鸿蒙配置文档** | `oh-package.json5`、`module.json5`、`build-profile.json5` | ⭐⭐ 中 | 鸿蒙模块配置（辅助参考） |
| **API 文档鸿蒙部分** | API 文档中包含鸿蒙化接口说明 | ⭐⭐ 中 | API 文档的鸿蒙化内容 |
| **示例文档鸿蒙部分** | example 目录中的鸿蒙化示例说明 | ⭐ 低 | 示例文档的鸿蒙化内容 |

#### 0.2 搜索执行流程

```bash
# Step 1: 搜索鸿蒙特定 README 文件（最高优先级）
# 注意：使用通配符匹配大小写变体和语言后缀变体（_CN, _zh 等）
find {sourceDir} -iname "README.*harmony*" -o -iname "README.*ohos*" -o -iname "README.*openharmony*" -type f

# Step 2: 同时检查根目录和包级子目录（如 kraken/, lib/ 等）
# Flutter 项目常见结构：根目录简版 + 包级详细版
find {sourceDir} -maxdepth 2 -iname "README.*harmony*" -o -iname "README.*ohos*" -o -iname "README.*openharmony*" -type f

# Step 3: 若未发现鸿蒙专属文档，才搜索 README.md 中的鸿蒙章节
grep -n -i "ohos|harmony|openharmony|鸿蒙|harmonyos" {sourceDir}/README.md

# Step 4: 搜索 CHANGELOG.md 中的鸿蒙化变更记录
find {sourceDir} -name "CHANGELOG.md" -type f | xargs grep -l -i "ohos|harmony|openharmony|鸿蒙|harmonyos"

# Step 5: 搜索 example 目录中的鸿蒙化示例说明
find {sourceDir} -path "*/example/*" -name "README.md" -type f | xargs grep -l -i "ohos|harmony|openharmony|鸿蒙"
```

#### 0.3 鸿蒙化文档定位结果分类

根据搜索结果，将文档分为以下类别：

```
检视范围判定：
├── 鸿蒙核心文档（必检视）
│   ├── README.OpenHarmony.md / README.openharmony.md ✅ 检视（最高优先级）
│   ├── README.OpenHarmony_CN.md / 中文变体          ✅ 检视（最高优先级）
│   ├── README.harmony.md                            ✅ 检视（最高优先级）
│   ├── README.ohos.md                               ✅ 检视（最高优先级）
│   ├── 包级子目录同名文件（如 kraken/README.OpenHarmony.md）✅ 检视（最高优先级）
│   ├── CHANGELOG.md 鸿蒙变更                        ✅ 检视
│   └── API 文档鸿蒙接口说明                         ✅ 检视
├── 鸿蒙替代文档（仅当专属文档不存在时检视）
│   └── README.md 鸿蒙章节                           ⚠️ 替代检视（专属文档缺失时）
├── 鸿蒙辅助文档（辅助检视）
│   ├── oh-package.json5 说明                        ⚠️ 辅助参考
│   ├── module.json5 说明                            ⚠️ 辅助参考
│   └── example 鸿蒙示例                             ⚠️ 辅助参考
├── 非鸿蒙文档（不检视，不扣分）
│   ├── README.md 上游原始内容                       ❌ 不检视、不扣分（如 Android/iOS 说明）
│   ├── CHANGELOG.md 其他变更                        ❌ 不检视
│   ├── API 文档非鸿蒙接口                           ❌ 不检视
│   └── example 其他平台示例                         ❌ 不检视
```

#### 0.4 判定规则

| 搜索结果 | 判定 | 评分 | 后续操作 |
|----------|------|------|----------|
| 发现 `README.OpenHarmony.md` 等（含 `_CN` 变体、包级文件） | ✅ 存在鸿蒙专属文档 | 正常评分 | 进入 Phase 1 深度检视，**README.md 不纳入鸿蒙化扣分** |
| 仅 README.md 包含鸿蒙章节（无专属文档） | ⚠️ 缺少专属文档 | 正常评分但1.1扣15分 | 进入 Phase 1，检视 README.md 鸿蒙章节替代专属文档 |
| 仅发现配置文件无说明文档 | ⚠️ 文档缺失严重 | 20-40 分 | 报告标注"鸿蒙化文档严重缺失" |
| 未发现任何鸿蒙文档特征 | ❌ 鸿蒙化文档缺失 | **0 分** | 报告标注"未发现鸿蒙化相关文档" |
| 无法访问源码目录 | ❌ 无法检视 | **0 分** | 报告标注"源码目录不可访问" |

**重要说明**：
- **上游 README.md 不扣分**：README.md 通常是上游原始项目文档，鸿蒙化内容应放在 README.OpenHarmony.md 等专属文档中。**当专属文档存在时，README.md 缺少鸿蒙内容不扣分**
- **专属文档优先**：README.OpenHarmony.md 等鸿蒙专属文档是检视核心，缺失将严重扣分
- **多层级文档**：根目录简版 + 包级详细版 是常见的合理结构，两者均需检视

### Phase 1：鸿蒙化文档完整性检查（致命项，40分）

#### 1.1 鸿蒙专属文档存在性检查（致命项，15分）

| 检查项 | 要求 | 扣分规则 |
|--------|------|----------|
| README.OpenHarmony.md 等存在 | 应有鸿蒙专属 README 文件（含 `_CN` 变体） | **缺失扣 15 分（致命）** |
| 鸿蒙文档位置正确 | 位于根目录、docs 目录或包级子目录 | 位置不当扣 3 分 |
| 鸿蒙文档命名规范 | 使用标准命名格式（大小写不扣分） | 命名不规范扣 2 分（大小写不扣分） |
| 鸿蒙文档内容非空 | 文档内容不为空或仅占位符 | 为空扣 10 分 |

#### 1.2 README.md 鸿蒙章节完整性（严苛项，15分）

**关键规则**：本节仅在**不存在鸿蒙专属文档时**启用。当 README.OpenHarmony.md 等专属文档存在时，README.md 作为上游原始文档，其缺少鸿蒙内容**不扣分**，本节直接满分 15 分。

**场景 A：鸿蒙专属文档存在 → 本节满分 15/15，无需检视 README.md 鸿蒙章节**

**场景 B：鸿蒙专属文档不存在 → 检视 README.md 鸿蒙章节替代专属文档**：

| 检查项 | 要求 | 扣分规则 |
|--------|------|----------|
| 鸿蒙平台支持说明 | README.md 明确说明支持鸿蒙/OpenHarmony 平台 | **缺失扣 10 分** |
| 鸿蒙安装配置说明 | README.md 提供鸿蒙平台的安装和配置步骤 | 缺失扣 8 分 |
| 鸿蒙平台差异说明 | README.md 说明鸿蒙平台与其他平台的差异 | 缺失扣 5 分 |
| 鸿蒙版本要求说明 | README.md 说明鸿蒙系统版本要求 | 缺失扣 5 分 |

#### 1.3 Flutter 版本对应关系说明（致命项，10分）

**这是用户明确要求的核心检查项**：

| 检查项 | 要求 | 扣分规则 |
|--------|------|----------|
| Flutter 版本对应说明 | 清晰说明 Flutter 框架版本与三方库版本对应关系 | **缺失扣 10 分（致命）** |
| 版本对应表完整 | 提供版本对应表，包含关键维度列 | 缺少关键列扣 5 分 |
| 版本兼容性说明 | 说明版本兼容性和不兼容情况 | 缺失扣 3 分 |
| 升级迁移说明 | 说明版本升级的迁移方法 | 缺失扣 2 分 |

**版本对应表完整性判定**：

| 情况 | 判定 | 扣分 |
|------|------|------|
| 表格仅有当前版本一行数据（新适配库常见） | ✅ 合理完整 | **0 分** |
| 表格缺少关键维度列（如缺少 Flutter 框架版本列、TAG 列、分支列） | ⚠️ 不完整 | -5 分 |
| 表格信息与接口规格说明不一致 | ⚠️ 不准确 | -3 分 |
| 完全无版本对应表 | ❌ 致命缺失 | -10 分 |

**版本对应说明示例**：

```markdown
### TAG 版本对应表

| Flutter 框架版本 | TAG | 分支 |
|-----------------|-----|------|
| 3.22            | 4.2.3-ohos-1.0.0-beta.1 | br_3.27 |
| 3.27            | 4.2.3-ohos-1.0.0-beta.1 | br_3.27 |
| 3.35            | 4.2.3-ohos-1.0.0-beta.1 | br_3.27 |
```

### Phase 2：鸿蒙化接口说明准确性检查（严苛项，30分）

> ⚠️ **准确性交叉验证**：本 Phase 要求**读取 `{interfaceDocPath}`（接口规格说明.md）**，将文档中的 API 名称、参数类型、版本信息与接口规格说明进行对比，确保文档描述与实际实现一致。

#### 2.1 鸿蒙化接口说明完整性（严苛项，10分）

**这是用户明确要求的核心检查项**：

| 检查项 | 要求 | 扣分规则 |
|--------|------|----------|
| 鸿蒙化接口列表 | 文档列出所有鸿蒙化实现的接口，标注 OHOS 支持状态 | **缺失扣 6 分** |
| 接口功能说明 | 每个鸿蒙化接口有清晰的功能说明 | 缺失扣 3 分 |
| 接口使用示例 | 提供接口使用示例代码 | 缺失扣 2 分 |

#### 2.2 三方库调用方式说明（严苛项，10分）

**这是用户明确要求的核心检查项**：

| 检查项 | 要求 | 扣分规则 |
|--------|------|----------|
| 调用方式说明 | 清晰说明三方库的调用方式（依赖添加 → 导入 → 创建 → 使用） | **缺失扣 10 分** |
| OHOS 环境配置步骤 | 提供详细的 OHOS 开发环境配置步骤（DevEco、SDK、编译） | 缺失扣 5 分 |
| 调用示例代码 | 提供完整的调用示例代码 | 缺失扣 5 分 |

#### 2.3 接口文档与库内文档双向对照（致命项，10分）

> ⚠️ **双向对照核心机制**：本节要求**读取 `{interfaceDocPath}`（接口规格说明.md）**与**库内鸿蒙化文档**（README.OpenHarmony.md 等）进行**双向逐项对比**，确保接口规格说明中的每个接口在库内文档中都有描述（正向覆盖度），且库内文档描述的每个接口在接口规格说明中都有对应定义（反向一致性）。

##### 2.3.1 正向对照：接口规格说明 → 库内文档覆盖度（5分）

**检查思路**：从接口规格说明出发，逐一验证库内文档是否覆盖了每个接口。

| 检查项 | 验证方法 | 扣分规则 |
|--------|----------|----------|
| 接口覆盖完整性 | 读取接口规格说明中列出的每个接口（类名/方法名），在库内文档中搜索是否均有描述 | 覆盖率 <80% 扣 3 分，<50% 扣 5 分 |
| 关键属性覆盖 | 检查库内文档是否描述了接口规格说明中的关键属性（参数列表、返回值、异常说明） | 遗漏关键属性每项扣 1 分，上限 3 分 |
| 参数说明对照 | 对比接口规格说明中每个接口的参数（名称、类型、可选/必填），与库内文档描述是否一致 | 不一致每处扣 1 分，上限 3 分 |

**正向对照执行流程**：
```
1. 读取接口规格说明.md，提取所有接口清单：
   - 类名/方法名列表
   - 每个接口的参数（名称、类型、可选/必填）
   - 每个接口的返回值类型
   - 每个接口的异常/错误说明

2. 对每个接口，在库内文档中搜索：
   - 接口名是否被提及（直接引用或自然语言描述）
   - 参数是否被说明（名称和类型是否一致）
   - 返回值是否被说明

3. 计算覆盖率：
   覆盖率 = 库内文档覆盖的接口数 / 接口规格说明中接口总数
   - ≥80% → 不扣分
   - 50%-79% → 扣 3 分
   - <50% → 扣 5 分
```

##### 2.3.2 反向对照：库内文档 → 接口规格说明一致性（5分）

**检查思路**：从库内文档出发，逐一验证文档描述的接口在接口规格说明中是否有对应定义，防止文档描述了不存在的接口（文档幻觉）或属性描述与实际不一致。

| 检查项 | 验证方法 | 扣分规则 |
|--------|----------|----------|
| 文档接口存在性 | 库内文档描述的每个接口（类名/方法名），在接口规格说明中搜索是否有对应定义 | 描述了不存在的接口每处扣 2 分，上限 5 分 |
| 属性类型一致性 | 对比库内文档与接口规格说明中同一接口的属性类型（参数类型、返回值类型） | 类型不一致每处扣 1 分，上限 3 分 |
| 版本信息准确性 | 文档版本号 vs 接口规格说明中的版本信息 | 不一致扣 2 分 |

**反向对照执行流程**：
```
1. 从库内文档中提取所有描述的接口：
   - 文档中提到的类名/方法名
   - 文档中声明的参数类型和返回值
   - 文档中的版本号和兼容性说明

2. 对每个文档描述的接口，在接口规格说明中验证：
   - 接口是否存在于规格说明中
   - 参数类型是否与规格说明一致
   - 返回值类型是否与规格说明一致

3. 识别文档幻觉：
   - 库内文档描述了接口规格说明中不存在的接口 → 严重问题
   - 库内文档的参数类型与规格说明不一致 → 中等问题
   - 库内文档的返回值类型与规格说明不一致 → 中等问题
```

**双向对照结果汇总表格式**：

| 对照方向 | 接口名 | 库内文档状态 | 接口规格说明状态 | 差异说明 |
|----------|--------|------------|---------------|----------|
| 正向 | XxxClass.methodA | ✅ 已描述 | ✅ 已定义 | 参数类型不一致：文档 String vs 规格 int |
| 正向 | XxxClass.methodB | ❌ 未描述 | ✅ 已定义 | 库内文档遗漏此接口 |
| 反向 | YyyClass.methodC | ✅ 已描述 | ❌ 未定义 | 文档幻觉：规格说明中不存在此接口 |

### Phase 5：严苛评分计算

#### 评分维度权重

```
总分 = 鸿蒙文档完整性(40) + 接口说明准确性(30) + 文档易读性(20) + 鸿蒙示例(10)
```

#### 严苛扣分规则

```
致命问题（直接严重扣分）：
- 缺少 README.OpenHarmony.md 等鸿蒙专属文档 → -15 分
- 缺少 Flutter 版本对应关系说明 → -10 分
- 鸿蒙化接口说明完全缺失 → -6 分
- 三方库调用方式说明缺失 → -10 分
- 鸿蒙文档内容为空或仅占位符 → -10 分（特殊：直接0分）
- 接口规格说明中接口在库内文档覆盖率 <50% → -5 分（双向对照致命）
- 库内文档描述了接口规格说明中不存在的接口（文档幻觉）→ -2~5 分（双向对照致命）

严重问题（仅当鸿蒙专属文档不存在时适用）：
- README.md 无鸿蒙平台支持说明 → -10 分（⚠️ 当专属文档存在时不扣此分）
- 鸿蒙化接口列表缺失 → -6 分
- 鸿蒙安装配置说明缺失 → -8 分
- OHOS 环境配置步骤缺失 → -5 分

中等问题：
- 文档结构不清晰 → -3~5 分
- 鸿蒙化内容描述冗长 → -3 分
- 版本对应表缺少关键维度列 → -5 分
- 接口规格说明中接口在库内文档覆盖率 50%-79% → -3 分
- 接口参数/返回值类型与规格说明不一致 → -1~3 分
- 库内文档遗漏接口规格说明中的关键属性 → -1~3 分

轻微问题：
- 鸿蒙示例不完整 → -2~4 分
- 示例注释缺失 → -2 分
- 错别字（含繁简混用） → -2 分/处
- 章节编号跳号 → -1 分

特殊规则（直接 0 分）：
- 未发现任何鸿蒙化相关文档 → 0 分
- 鸕蒙文档完全为空或仅占位符 → 0 分
- 累计扣分超过 50 分 → 最低 0 分
```

#### 最终评分公式

```
基础分数：100 分
扣分合计：各维度扣分累加
最终得分 = max(0, 100 - 扣分合计)
```
