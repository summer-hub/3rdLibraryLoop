# RN 鸿蒙三方库功能测试验证指引

这个 skill 是三方库升级适配流程的最后一步。目标是基于前序阶段的适配变更清单和测试用例，自动生成结构化的功能测试清单，标注高风险场景，关联历史稳定性问题，输出可执行的人工测试 checklist。

## 何时使用

- 用户已完成代码适配和测试对齐，需要生成功能测试清单。
- 用户想知道本次升级有哪些功能需要重点测试。
- 用户需要一份可交给 QA 的测试 checklist。
- 用户想了解升级后可能复现的历史稳定性问题。
- 用户想评估变更的影响范围和风险等级。

## 最小必要输入

- **必要**：适配变更清单（来自 rnoh-lib-code-adapt，记录改了哪些文件和内容）
- **有帮助**：diff patch 文件或变更摘要（来自 rnoh-lib-version-diff）
- **有帮助**：测试覆盖率报告（来自 rnoh-lib-test-align）
- **有帮助**：RNOH 版本信息（如 0.77→0.84）

如果用户没有适配变更清单，但有 diff patch 文件，可以从 diff 中提取变更清单。
如果什么都没有，引导用户先使用 rnoh-lib-version-diff 和 rnoh-lib-code-adapt。

## 工作流

### 第 1 步：提取变更影响范围

从适配变更清单和 diff 文件中，提取所有变更并分析其功能影响。

#### 变更影响分类

| 变更类型 | 功能影响 | 测试优先级 | 测试方式 |
|----------|---------|-----------|---------|
| 新增 API | 新功能可用 | 高 | 功能测试 |
| 修改 API 签名 | 调用方式变更 | 高 | 回归测试 |
| 删除 API | 旧功能不可用 | 高 | 兼容性测试 |
| 新增组件 Prop | 组件新属性 | 高 | 功能测试 |
| 修改组件行为 | 显示/交互变化 | 高 | 视觉+功能测试 |
| 原生层修改 | C++/ArkTS 变更 | 最高 | 稳定性+功能测试 |
| Codegen 产物变更 | TurboModule/Fabric 变更 | 最高 | 全量回归 |
| JS 层逻辑修改 | 业务逻辑变化 | 中 | 功能测试 |
| 依赖版本升级 | 传递性影响 | 中 | 回归测试 |
| 配置文件修改 | 构建配置变化 | 低 | 编译验证 |

#### 影响范围分析

对每个变更，回答以下问题：

1. **这个变更影响哪些功能？** — 列出受影响的功能点
2. **这个变更影响哪些组件？** — 列出受影响的组件
3. **这个变更是否影响生命周期？** — 初始化、渲染、销毁阶段
4. **这个变更是否涉及线程安全？** — 多线程访问、回调时序
5. **这个变更是否影响内存管理？** — 资源分配、释放

### 第 2 步：生成功能测试清单

基于变更影响范围，生成结构化的功能测试清单。

#### 测试清单结构

```markdown
# 功能测试清单

## 基本信息
- 三方库名称: <lib-name>
- 升级版本: <old-version> → <new-version>
- RNOH 版本: <old-rnoh> → <new-rnoh>
- 生成日期: <date>

## 测试清单

### 一、新增功能测试

#### 1.1 [P0] 新增 API: getXxx()
- **变更来源**: v7.4.0 新增
- **测试步骤**:
  1. 调用 `NativeModule.getXxx(param)`
  2. 验证返回值类型和内容正确
  3. 测试异常参数（null/undefined/错误类型）
  4. 测试并发调用
- **预期结果**: 正常返回结果，异常参数有合理错误处理
- **风险等级**: 🔴 高

#### 1.2 [P0] 新增组件 Prop: renderMode
- **变更来源**: v7.4.0 新增
- **测试步骤**:
  1. 设置 `renderMode="automatic"`
  2. 设置 `renderMode="hardware"`
  3. 切换 renderMode 后验证渲染效果
  4. 不设置 renderMode 验证默认值
- **预期结果**: 不同模式渲染正确，切换无闪烁
- **风险等级**: 🟡 中

### 二、回归测试

#### 2.1 [P0] 基本功能回归
- **测试范围**: 所有已有功能
- **测试步骤**:
  1. 组件基本渲染
  2. 所有已有 Props 验证
  3. 所有已有事件回调验证
  4. 组件挂载/卸载
- **预期结果**: 与升级前行为一致
- **风险等级**: 🔴 高

#### 2.2 [P1] 性能回归
- **测试步骤**:
  1. 大量组件同时渲染
  2. 频繁 props 更新
  3. 长时间运行后内存占用
  4. 动画帧率
- **预期结果**: 性能无明显退化
- **风险等级**: 🟡 中

### 三、稳定性测试

#### 3.1 [P0] 页面销毁后回调
- **变更来源**: 原生层修改
- **测试步骤**:
  1. 进入组件页面
  2. 立即返回（触发销毁）
  3. 检查是否有崩溃/泄漏
  4. 重复 10 次
- **预期结果**: 无崩溃，无内存泄漏
- **风险等级**: 🔴 高

#### 3.2 [P0] 快速切换页面
- **测试步骤**:
  1. 快速在组件页面和其他页面间切换
  2. 每次切换间隔 < 500ms
  3. 持续 30 秒
  4. 检查应用状态
- **预期结果**: 无崩溃，无卡死
- **风险等级**: 🔴 高

### 四、兼容性测试

#### 4.1 [P1] React 版本兼容
- **变更来源**: React 18→19 升级
- **测试步骤**:
  1. 验证 Hooks 正常工作
  2. 验证 Refs 正常工作
  3. 验证 StrictMode 无警告
- **预期结果**: 无兼容性问题
- **风险等级**: 🟡 中
```

### 第 3 步：标注高风险场景

根据变更类型和历史经验，标注需要重点关注的高风险场景。

#### 高风险场景判断标准

| 判断维度 | 高风险信号 |
|----------|-----------|
| 变更位置 | 涉及 C++ 框架层、TurboModule 实现、Fabric 组件实例 |
| 变更时机 | 涉及生命周期（初始化、销毁、重载） |
| 变更性质 | 涉及线程同步、内存管理、资源释放 |
| 变更规模 | 原生层修改超过 100 行 |
| 版本跨度 | 跨大版本升级（如 0.72→0.84） |
| 历史问题 | 该模块曾有稳定性修复记录 |

#### 高风险场景清单模板

```markdown
## ⚠️ 高风险场景预警

### 🔴 风险1: TurboModule 销毁后回调
- **触发条件**: 页面快速退出时 TurboModule 异步回调仍在执行
- **关联变更**: NativeXxxModule.ts 新增异步方法
- **历史参考**: 0.77 分支曾有类似 UAF 修复
- **建议**: 重点测试快速退出场景，检查 FaultLog

### 🔴 风险2: 组件内存泄漏
- **触发条件**: 组件频繁挂载/卸载
- **关联变更**: 新增 Props 导致 ArkUI 节点持有额外引用
- **历史参考**: 0.82 分支曾有组件实例未释放修复
- **建议**: 使用 HiTrace 工具监控内存，重复挂载卸载 20+ 次

### 🟡 风险3: 动画帧率退化
- **触发条件**: 多个动画组件同时运行
- **关联变更**: renderMode 新增可能影响渲染路径
- **建议**: 对比升级前后的帧率数据
```

### 第 4 步：关联历史稳定性问题

检查工作区中的历史稳定性修复文档，预警可能复现的问题。

#### 历史问题检索路径

优先查看以下文档（如果工作区中存在）：

1. `docs/开发者指南/05-分发运维/稳定性历史修复/0.72稳定性修复汇总/`
2. `docs/开发者指南/05-分发运维/稳定性历史修复/0.77稳定性修复汇总/`
3. `docs/开发者指南/05-分发运维/稳定性历史修复/0.82稳定性修复汇总/`
4. `docs/开发者指南/05-分发运维/稳定性问题介绍/稳定性案例.md`

#### 检索策略

1. 根据变更涉及的模块名称，在历史修复文档中搜索相同模块
2. 根据变更涉及的变更类型（UAF、泄漏、死锁等），在历史修复文档中搜索相同类型
3. 只检索用户当前版本之后的历史修复（与 rnoh-stability-triage 的版本边界规则一致）
4. 对找到的历史问题，判断当前变更是否可能复现

#### 关联报告格式

```markdown
## 历史稳定性问题关联

### 已检查的历史修复

| 版本分支 | 模块 | 问题类型 | 是否可能复现 | 说明 |
|----------|------|---------|-------------|------|
| 0.77 | AnimatedModule | UAF | ⚠️ 可能 | 本次新增异步回调，存在同类风险 |
| 0.82 | ImageComponent | 内存泄漏 | ✅ 低风险 | 本次未修改图片相关代码 |
| 0.82 | FontRegistry | 空指针 | ✅ 低风险 | 本次未修改字体相关代码 |

### 建议重点关注的历史修复

1. **0.77: AnimatedModule UAF 修复** (PR #xxx)
   - 问题: VSync 回调在模块销毁后执行
   - 当前风险: 本次新增的异步方法有类似时序风险
   - 测试建议: 重点测试快速退出场景
```

## 常见边界情况

### 1. 没有适配变更清单

如果用户没有结构化的适配变更清单：
- 从 diff patch 文件中提取变更文件列表
- 用 `git diff` 或读取 patch 文件内容自行分析变更
- 生成简化版测试清单（基于文件变更而非逐项变更）

### 2. 跨大版本升级

跨大版本升级（如 0.72→0.84）的测试清单需要额外关注：
- 中间每个版本的不兼容变更都可能有功能影响
- 需要做全量回归测试而非增量测试
- 历史稳定性问题检索范围更大

### 3. 纯 JS 层升级

如果变更全部是 JS 层（无原生层修改）：
- 风险等级整体降低
- 重点关注 JS 逻辑正确性和 API 兼容性
- 可以减少稳定性测试项

## 输出物

完成本 skill 后，产出一份完整的功能测试 checklist 文档（Markdown 格式），包含：

1. **变更影响范围分析** — 每个变更的功能影响和测试优先级
2. **功能测试清单** — 按 P0/P1/P2 分级的测试项
3. **高风险场景预警** — 标注需要重点关注的场景及原因
4. **历史稳定性问题关联** — 可能复现的历史问题及测试建议
5. **可执行 checklist** — 可直接打印给测试人员使用的勾选清单
